##### RAG和Memory构建
###### RAG
本质就是密集的向量搜索  context engineer决定把什么内容放进上下文，内外循环，舍弃多无用的token干扰
首先第一部分是知识库构建，这部分主要的目的就是希望模型在回答问题的时候通过我们提供的专业背景知识来消除幻觉，提升大模型在专业领域的能力，相比于sft的方式有更低的成本和可移植性。主要的方式就是将知识文档切块，转化成向量模型嵌入到向量知识库中，在收到用户提问后首先再知识库中进行向量相似度检索，召回相应的文档片段作为上下文给到模型辅助生成回答。这个流程主要分为嵌入和召回阶段，要做优化也是从这两个阶段去做考虑，在嵌入阶段对召回结果产生影响的主要是选用的embedding模型的性能，对文档块的切分策略。召回阶段主要涉及对query的处理，重排序，优化底层检索算法等等。当然还有文档本身的质量。针对这两个阶段对应的优化方式也很多。
两期，第一期
首先是嵌入阶段，对比了十几embedding模型，最后根据效果选定了两种，一种是1024维度的平衡速度与质量，一种是qwen3-8b，4096维度，能够提供更高的精度。
文档切块这里首先通过工具将各种格式的文档转换成markdown格式，在固定分块的基础上可以结合文档结构进行分块。召回这里最开始是使用了一个query拆分和改写模型，重新切分组织用户的query语言，增加信息的丰富度能够一定程度上的提升召回率。
第二期在公司其他bg的工作分享发现了一个优化点，在嵌入过程中做处理。原来我在做个人项目的时候就用到了父文档检索这样一种方式，将文档分割成小块，更适合精确的向量相似度检索，小块保留链接到更大的父模块，检索时先用查询向量匹配小块，然后返回对应的父块，这样在检索过程中减少冗余信息的干扰。其他部门的工作整体思路和这个类似，是通过在文档嵌入时使用一个小模型做qa对提取，这个模型是 通过微调加强化学习的方式训练出来的专门针对文档信息提取成多个query-answer的方式，相当于把文档内的关键信息给抽取出来了。这样我们在做嵌入的时候就可以只把query嵌入进去，维护一个指向文档的链接，同时将生成的answer拼接到对应文档块的头部。相当于检索的时候用户的query和提取出来的query去做匹配，返回的是answer+文档块，这样就大大提升了召回效率。另外在工程上还针对业务场景有一些版本管理，增量更新，定时更新等专门的优化策略。
- 检索算法
FLAT：100%召回，全部搜索。
倒排索引IVF：通过聚类将整个向量空间划分为k个相对紧凑的分组，检索时计算查询向量与聚类中心的距离，仅在与query最相似的nprob个分组里进行精确的向量。
优势：通过限制搜索范围显著降低了计算量。内存消耗相对较低（主要存储聚类中心和分组指针），尤其擅长处理十亿级甚至更大规模的数据集。结构简单，确定性较好。
局限：召回率（Recall）高度依赖于聚类质量和nprobe参数。nprobe越大，召回越高，但计算开销也线性增加。在数据分布极其复杂或聚类边界模糊时，达到高召回需要付出较大计算代价。
图索引Graph：将每个样本向量视为图中的一个顶点（Vertex），并根据向量间的相似度（距离）建立边（Edge）连接其最近邻。
优势：利用图的连通性和“小世界”特性，通常能在非常低的计算量下实现极高的召回率（接近100%）。对数据分布不敏感，适应性更强。
局限：构建过程较复杂，内存消耗相对较高（需要存储图结构，包括邻居列表）。搜索路径具有一定随机性，性能可能受起始点影响。在大规模数据集上，维持高召回和高性能需要更精巧的结构设计。
HNSW：多层图构建，底层包含所有数据点，构建稠密图，上层只包含下层的一个随机子集，并构建更稀疏的图，最顶层是最稀疏的图。搜索时由上至下，在稀疏层进行贪婪搜索，快速定位到大致区域，逐层向下找到最佳点作为下一层的入口，最终在底层为完成精确的近似查找。
局限：上层图的构建基于随机选择，其导航能力虽然强大但具有不确定性，并非最优表示整体空间结构。构建多层图和存储邻居列表带来较高的内存开销。
###### Memory
记忆这部分核心的思路就是通过将之前的对话信息和当前轮次的输入一起给到大模型，让模型能够结合之前的对话信息回答。大模型本身是不能记住之前的交流内容的，这首先会导致缺乏对话连贯性，无法深入，其次一但缺乏对应的事实依据的时候极易产生幻觉或捏造信息。最简单的记忆方案大体有两种，一个就是将全部的上下文都作为记忆传给模型，另一个就是将上下文使用模型做一个summary提取关键信息，第一种方案很容易造成长度超过模型限制，直接做summary在少轮次对话场景下又容易丢失信息，我们这里选择了结合这两种方式，通过滑动窗口+阈值出发summary的方式，初始时向窗口中添加全部上下文，当窗口信息达到模型阈值的90%时出发summary，总结后的信息加到窗口里继续拼接后续的对话信息。另外加入了长记忆机制，针对业务的特点设计了用户画像，以session为单位进行长记忆更新。这里其实也尝试了使用固定轮次，关键词，时间几种触发更新的方式，但是最终发现session的效果最好，另外支持对长记忆的信息进行重写。另外现在也有专门针对agent的通过强化学习的方式来训练memory模型的方法，后续可以作为迭代版本进行优化。

- Mem0：关键在于其独特的双阶段记忆处理流程——提取（Extraction）和更新（Update）。这一设计旨在确保系统只存储和检索最相关的事实，从而将Token消耗和延迟降至最低。
提取阶段（Extraction）：
信息输入：系统会同时从三个来源获取上下文：最新的一轮交流、一个动态滚动的摘要，以及最近的 m 条消息。
记忆生成：利用大语言模型（LLM）从这些信息中提炼出一组简洁的候选记忆。
异步刷新：一个后台模块会异步地、不间断地刷新长期摘要，确保核心推理过程永远不会因为记忆管理而停顿。
更新阶段（Update）：
相似度比对：每一个新生成的候选记忆，都会与向量数据库中Top-k个最相似的已有记忆进行比较。
智能决策：随后，大语言模型会根据比对结果，在以下四种操作中做出智能决策：
添加（ADD）：存入一条全新的记忆。
更新（UPDATE）：用新信息迭代或合并一条现有记忆。
删除（DELETE）：移除与新事实矛盾或已过时的旧记忆。
无操作（NOOP）：如果无需更改，则不执行任何操作。

###### 后续优化
目前还没有专门训练这种用户memory总结的LLM，现有的面临外推时性能下降，总结时选择性信息保留困难，缺乏保存关键事实同时丢弃干扰因素的能力。
后续希望使用强化学习的方式来训练模型，目前了解了两种思路，一种是将文本分成固定段，使用模型依次阅读这些短，过程中维护一个query相关的memory，在最后依据memory回答问题，这个过程可以建模成MDP（马尔可夫决策过程），使用强化学习进行训练。
三层循环：
外循环：一次完整的长文本问答任务；中循环：文档被切成登场chunk；内循环：每个chunk再拆成k轮子对话，让agent与固定LLM交互，逐渐精炼记忆。
训练过程中冻结大模型，外挂一个小模型，用于生成prompt诱导大模型输出新的记忆文本，把原本的conversion-level的重写记忆建模成token-level的任务
后续要训练专门针对于agent的memory总结模型，因为当前的模型在面对长序列输入时


#### 补充
后续方向
当前做的工作还是基于单个Agent来构建智能助手，现在的很多研究已经进展到了mult-agent阶段，不同的Agent之间可以协同完成任务，就像一个agent可以调用多个MCP一样，现在也有了一些A2A的框架，这可能是未来的一个进展方向
agent强化学习，当前的强化学习方法在面对长时序agent训练时存在信用分配困难，将整个轨迹视为一个整体来进行相对优势估计，无法为多步决策中的单个动作提供精细反馈信号，在长时序环境交互中奖励稀疏且延迟。这方面可能后续会优化。针对不同轨迹的相同状态，利用这些重复状态做锚点来构建步骤级的group，将轨迹和步骤结合起来作为最终的优势函数。

### 零散
#### 基础
1. 判断无向图连通
核心算法：深度优先搜索（DFS）或广度优先搜索（BFS）
这两种算法都可以通过遍历图来检查连通性。基本思想是：从任意一个顶点出发，如果能访问到所有顶点，则图是连通的；否则，图是非连通的。
算法步骤（以DFS为例）：
初始化：创建一个visited数组（或集合），记录每个顶点是否被访问过，初始时所有顶点标记为未访问。
开始遍历：从任意一个顶点（如顶点0）开始，执行DFS遍历。
递归遍历：在DFS过程中，访问当前顶点，并递归地访问其所有未访问的相邻顶点。
检查覆盖情况：遍历结束后，如果visited数组中所有顶点都被标记为已访问，则图是连通的；否则，图是非连通的。

2. 大型分布式系统中判断一个非常大的无向图的连通性
分布式连通分量算法
算法原理：基于标签传播（如Union-Find的分布式版本）。每个节点初始拥有自己的唯一ID（如节点ID），在迭代过程中，每个节点将自身ID与邻居ID比较，并更新为最小ID。多轮迭代后，所有连通的节点会收敛到相同ID。如果最终所有节点ID相同，则图连通。
优化点：
图分区：使用哈希或范围分区将图分割成多个块，分布到不同工作节点，最小化跨分区边的数量（如使用Metis等工具预分区）。
压缩路径：在Union-Find中应用路径压缩和按秩合并，减少迭代轮数。
增量更新：如果图是动态的，只重新计算受影响的分区，而不是全图重算。

3. 在分布式环境下使用标签传播算法（如连通分量计算）时，网络延迟或节点状态更新不同步可能导致以下问题及应对策略：
一、可能导致的问题
算法不收敛或收敛缓慢：
延迟会导致节点接收邻居消息的时间不一致，可能使标签更新陷入循环或无法全局一致，从而延长迭代轮数，甚至无法收敛到正确连通分量。
结果不一致或错误：
部分节点更新滞后可能使系统暂时处于“分裂”状态（如同一连通分量中出现多个标签），导致最终结果不准确，误判图的连通性。
二、应对策略
引入异步更新机制：
允许节点独立更新标签，而不严格等待所有邻居同步。例如，使用基于时钟的异步模型（如时间戳），节点只处理最新消息，避免旧状态干扰。这能提高鲁棒性，但需设计冲突解决策略（如始终选择最小标签）。
添加容错和一致性保障：
采用分布式一致性协议（如Paxos或Raft）在关键步骤（如标签合并）达成共识，确保即使有延迟，系统也能最终一致。也可以使用版本向量（Vector Clocks）检测和解决状态冲突。

4. 深拷贝和浅拷贝的区别
浅拷贝：只复制对象本身，不复制对象内部引用的可变子对象；
拷贝后的新对象与原对象共享内部子对象。
深拷贝：递归复制对象及其所有子对象；
拷贝后的新对象与原对象完全独立，互不影响。
举一个具体的例子说明浅拷贝可能导致的问题。以 Python 中的列表为例，假设我们有一个嵌套列表（即列表中包含其他列表），使用浅拷贝时，只会复制顶层对象，而嵌套对象仍然是共享的引用。这可能会导致意外行为。

5. 多线程使用浅拷贝
浅拷贝创建的新对象与原始对象共享其内部的可变子对象。当多个线程同时操作这些拷贝后的对象时，如果它们试图修改的是同一个共享的子对象，就会产生数据竞争。




#### 机器学习
1. 逻辑回归使用 Sigmoid 函数
出于概率解释、数学便利性和模型性质等多方面综合考虑的结果。
- 核心原因：将线性输出映射为概率
- 源自指数族分布（概率解释）
从统计学的角度看，逻辑回归的假设是：给定输入 x，输出标签 y服从伯努利分布。而 Sigmoid 函数正是伯努利分布（属于指数族分布）的规范链接函数推导出的自然结果。这意味着使用 Sigmoid 函数可以使模型具有概率意义上的最优性质。
- 数学上的便利性（易于求导）
Sigmoid 函数有一个非常优秀的数学性质：其导数可以用其自身表示。
- 良好的函数形状
Sigmoid 函数是“S”形曲线，具有以下特点：
中间区域敏感：在 z=0附近，函数曲线陡峭，对输入的变化非常敏感，分类决策明确。
两侧区域平滑：当 z趋向正负无穷时，函数值趋近于 0 或 1，且变化平缓。这使得模型对远离决策边界的异常点不敏感，具有一定的鲁棒性。

2. 为什么Sigmoid函数的形状和性质特别适合逻辑回归，以及其数学特性如何辅助概率映射。
- Tanh 函数（双曲正切函数）
函数公式：tanh(z) = (e^z - e^(-z)) / (e^z + e^(-z))或 tanh(z) = 2 * sigmoid(2z) - 1
值域：(-1, 1)
与Sigmoid的优劣对比：
优势：
零中心：输出以0为中心（均值为0），这在训练神经网络时具有巨大优势，因为下一层输入的均值是0，梯度下降的收敛速度通常比非零中心的Sigmoid函数更快、更稳定。
梯度更强：在相同的输入下，Tanh函数的梯度比Sigmoid函数更陡峭，意味着在关键区域信号更强。
劣势：
不适合直接作为二分类的概率输出：其值域为(-1, 1)，而概率需要(0, 1)的范围，因此不能像Sigmoid那样直接解释为概率 P(y=1|x)。在逻辑回归中，Sigmoid的直接概率解释是其不可替代的核心优势。
- Softmax 函数
功能：Sigmoid函数是二分类的特例，而Softmax函数是其在多分类问题上的推广。
如何工作：它将一个包含K个实数的向量“压缩”成另一个包含K个实数的向量，使得每个元素的范围在(0,1)之间，且所有元素的和为1。这完美地满足了多分类的概率分布要求。
与Sigmoid的关系：当类别数K=2时，Softmax函数等价于Sigmoid函数。
优劣：
优势：是多分类问题的标准解决方案，输出可以直接解释为每个类别的概率。
劣势：专用于多分类，在二分类问题上与Sigmoid等价，但形式稍复杂。
- ReLU 族函数（如ReLU, Leaky ReLU）及其变体
函数公式（ReLU）：ReLU(z) = max(0, z)
值域：[0, +∞)
对比：
优势：在深度学习（特别是深度神经网络）中，ReLU及其变体因其计算简单和有效缓解梯度消失问题而已成为隐藏层的默认选择，其训练收敛速度远快于Sigmoid/Tanh。
劣势：
值域不匹配：输出范围是[0, +∞)，完全不适合映射到概率(0, 1)。
不是S形曲线：不具备Sigmoid那种平滑的饱和特性。因此，ReLU族函数通常用作神经网络隐藏层的激活函数，但网络的最终输出层如果是为了表示概率，仍然会使用Sigmoid（二分类）或Softmax（多分类）。

#### 大模型
