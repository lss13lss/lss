# AI 为什么总要我重新解释？从 Agent 到自己的上下文

从“帮我写一篇文章”开始，理解 Agent 怎样做事、Context 提供什么，以及自己的笔记怎样在下一次协作中派上用场。

换一个 AI 工具，或者隔一段时间继续一个任务，有时又要重新解释：我在做什么，文章给谁看，哪些想法已经讨论过。这也是我整理个人上下文时一直关心的问题。要说明白这件事，可以先从一个具体任务出发。

## 同样是“帮我写一篇文章”，缺的可能是背景

假设我对 AI 说：“帮我写一篇关于阅读习惯的文章。”它可以给出一篇结构完整的文字。但如果我想写的是自己读两本书时的一次联想，它还缺少关键材料：我原来想到了什么，后来改了什么，以及哪些话才是我愿意表达的。

如果再补上原始笔记、读者是谁、一段自己的旧稿，以及“不要编造实践成果”这条要求，任务就具体了。这些信息给了它判断和取舍的依据。结果是否更合适，仍要看实际稿件。

“它懂不懂我”可以先拆成一个更容易检查的问题：这一次，它拿到了哪些与任务有关的信息？回答得不合适，也可能涉及模型能力、工具或要求本身，不能全归因于背景不足。

## Agent：围绕目标，决定下一步怎样做

在本文里，Agent 指一类由大模型根据任务进展选择步骤、调用工具的 AI 系统。模型参与判断，工具提供查资料、读文件等能力，程序负责把调用与结果接起来。不同资料对 Agent 的用法并不完全一致，这里采用的是这个含义。

[定义参考：Anthropic · Building effective agents](https://www.anthropic.com/research/building-effective-agents)

继续用写文章举例。在具备相应工具和权限的前提下，它可以先搜索笔记；找到材料后，判断还缺什么；需要核对时查阅来源；再写稿，并按要求检查。检查发现论据不足，下一步就可能是补证据，而不是立刻交稿。

关键在于它能够根据中间结果调整下一步。如果每个步骤早已写死，系统只按顺序执行，更接近预设工作流。两种方式都有用途，简单任务也可以直接用一次对话完成。

Agent 可以推进过程，但目标、可访问的资料和行动边界仍需要人来确定。拿到工具权限，也不代表它已经阅读了所有文件。

把这一轮拆开看，Agent 做的不是「回答一次」，而是读上下文、决定动作、调用工具、检查结果，再把结果写回记录。

## Context：这一次判断时，模型实际拿到的信息

Context 通常译作“上下文”。这里可以先把它理解为模型这一次处理任务时能用到的输入信息：要求、对话、相关资料，以及工具返回的结果。模型原有的能力和知识，与本次输入的上下文，是不同的部分。

[概念参考：Anthropic · Effective context engineering for AI agents](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

在刚才的写作任务里，上下文可以包含这些内容：

- 目标：把一段阅读联想写成面向初学者的短文。
- 材料：原始笔记、讨论后修正的认识，以及需要引用的书籍来源。
- 要求：保留个人语气，分清原话与整理，不把设想写成已经取得的成果。
- 过程信息：刚搜到了哪些内容，哪条来源还没核对，草稿哪里需要修改。

我们常说的提示词，可以包含任务指令，也可以附带材料和示例；它是提供上下文的一种方式。随着 Agent 查找资料、调用工具，后续步骤还会获得新的信息，上下文也会随之变化。

因此，Agent 和 Context 是两个相互关联的概念：前者描述如何组织行动，后者涉及每一步判断依据什么信息。

## 知识库、长期记忆和当前上下文，怎样接起来

我把笔记存进知识库，只完成了“留下来”。要让这篇笔记参与某一次写作，还需要找到相关内容，再把它提供给模型。这个选择可以由我手动完成，也可以交给具备检索或文件读取能力的系统。

可以借用一个书桌的比喻：知识库像书架，当前上下文像这次摊在桌面上的材料。书架上的东西很多，桌面上要放的是眼下这件事需要的部分。这个比喻只帮助理解信息的选择，不表示模型有人一样的记忆。

长期记忆则强调某些信息能跨任务保留，并在以后被调用。它可能记录偏好、项目状态或过去经验，也可能使用与知识库相同的文件和存储方式。两者会重叠，不必把它们想成互不相干的盒子。

> 保存资料 → 按任务找到相关内容 → 带入当前上下文 → 行动与检查

*个人知识进入协作的一条简化路径；发现缺失信息时，可以返回继续查找。*

这也解释了两种常见情况：一段信息虽然保存了，但这次没有被找到；或者找到了，却还是旧版本。前者需要检查检索和读取，后者需要检查更新时间与适用条件。仅仅多存一些笔记，不能自动解决它们。

## 为什么 Context 重要：让判断有具体依据

回到写作例子，如果缺少原始笔记，AI 很难区分“我确实这样想过”和“它替我补出来的一段合理表达”。如果只看到旧账号定位，它也可能沿用我已经调整过的方向。这些问题都关系到任务依据是否完整、准确和及时。

但更多背景并不总是更好。模型一次能处理的上下文有容量限制，即使材料放得下，也不能保证每处细节都被准确利用。无关内容、重复转述和相互冲突的版本，都值得筛选。

[进一步阅读：上下文的限制与信息筛选](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

对自己的记录，我会优先检查三件事：

- 这次有关吗？写阅读联想时，先找相关笔记和表达要求，不必搬进所有生活记录。
- 它可靠吗？保留出处，区分本人原话、AI 整理和还没核实的判断。
- 它还是当前的吗？目标改变后更新状态，把旧结论留作历史，不继续当成默认要求。

把背景准备得更好，是为正确判断创造条件。来源核对、结果审阅和必要的人工决定，仍然要做。

## 我正在尝试的，是让这些积累有一个可用的入口

在自己的文件系统里，我把已确认的个人信息、当前目标和协作偏好分别记录下来，再用一个入口文件说明：开始任务时先读哪些内容，遇到具体问题时再去找哪些笔记。这个安排让背景有地方可查，也方便回头修改。

实际使用中仍要检查 Agent 有没有按要求读取，旧信息有没有及时更新。能读到文件，与能恰当地使用内容之间，还有需要验证的距离。我目前也没有用长期对照证明，这套做法一定提高了多少效率。

如果你想先试一次，可以挑一个很小的任务，手动给它几条必要背景。下面是一份示范请求，方括号里的内容需要换成你自己的材料：

> 请根据下面这段笔记，帮我整理一篇约 500 字的阅读心得，给没读过这本书的人看。
> 
> 我的原始想法：[贴入一段自己的笔记]
> 我后来修正的认识：[写出变化；没有就说明没有]
> 表达参考：[贴入一小段自己的文字]
> 
> 请区分书中观点与我的理解，不要补造经历。材料不足的地方先指出来，最后由我审阅。

*示范请求；可以直接用在一次普通 AI 对话中。*

读完草稿时，可以对照检查：它保留了我的原意吗？有没有把猜想写成事实？哪些背景缺了，哪些其实用不上？先从一次具体结果发现问题，再决定下一次需要留下什么。

对我来说，阅读、思考和复盘本身就有价值。把相关部分整理成可用的上下文，又给了它们参与下一次协作的机会。后面的文章会分别记录我为什么做这件事、一次阅读认识的变化，以及怎样核对值得留下的观点。
