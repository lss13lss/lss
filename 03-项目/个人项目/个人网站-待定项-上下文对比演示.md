## 一、这个想法和站点是同一个命题

站点第一篇文章《AI 为什么总要我重新解释？》讲的正是这件事。这个演示等于把那篇的论点变成可触摸的东西——**读者不需要相信文字，自己看两栏输出就行**。从说服力看，这是全站最强的一个入口，强过任何定位文案。

所以它值得进计划，但**不值得在内容还只有 5 篇的时候做**：上下文太少，右栏的优势体现不出来，对比会显得像模型在瞎编。

## 二、三条硬约束（决定它能不能公开）

| 约束 | 具体风险 | 必须的做法 |
|---|---|---|
| **密钥** | API Key 放进前端 JS，等于公开发布；被人抓包后会拿你的额度刷到欠费 | 必须服务端代理，前端只调自己域名；密钥只在服务器环境变量里 |
| **滥用与成本** | 公开的免费问答入口一定会被当免费 API 用，费用无上限 | 每 IP 每日次数、单次输入长度上限、请求超时、**每日预算熔断**（如 5 元封顶自动停） |
| **生成内容合规** | 面向中国大陆公众提供生成式 AI 问答，涉及算法/大模型服务备案与内容安全责任 | 这条最可能让「实时版」直接不可行，需先确认，不要先做再补 |

第三条是真正的门槛。前两条是工程量，第三条是资质问题。

## 三、建议优先的替代方案：预生成静态对照

**不做实时 API，做离线跑好的对照样本。**

准备 20–30 组问题，把两栏回答离线生成、人工挑一遍，存成 JSON，页面只负责展示和切换。

- 成本 0、无需密钥、无限流、无合规风险、加载快、不怕挂
- **说服力几乎一样**：读者要看的是「差别」，不是「实时」
- 缺点：不能问自己的问题 → 留一个「想看你自己问题的效果？来信告我」的钩子，顺便变成读者互动入口

我的判断：**先做静态版，够用。** 真要上实时版，等有明确的人说"我想问自己的问题"再谈。

## 四、若确实要做实时版，前置条件

- [ ] 备案通过、域名可用、HTTPS 就绪
- [ ] 站点已有应用层能力（现在是纯静态 Nginx + 上传口，**没有任何后端**，这是新增的一层）
- [ ] 限流与预算熔断先跑通，再对公网开放
- [ ] 合规确认过（见第二节第三条）
- [ ] 建议先邀请制/口令路径，不直接放首页

## 五、公平对比的设计要点

否则就是伪对比，读者会当成营销话术：

- 两栏**同一个模型、同一个温度、同一个系统提示**，唯一变量是有无上下文
- 有上下文那栏要能**展开看到检索到哪几段**（RAG 的可解释性），否则读者会怀疑是硬编码的
- 问题要选「没上下文时模型含糊、有上下文时能具体」的类型；问「今天天气」这种，两栏没差别，等于自证无用

## 六、什么条件下提醒本人

任一满足即可提出，不必等全部：

1. 备案通过且域名可访问
2. 线上内容达到 **8–10 篇**（此时上下文量才够形成可见差异）
3. 本人主动问起
