# 个人网站定位调整（V3：以真实积累为主体）

> [!info] 一句话
> 视觉不动，改「先让访客看到什么」。首页从「个人上下文搭建教程」回到「我读了什么、想了什么、做了什么」，建教程降为其中一条分支。

部署、服务器、备案的硬信息都在 [[个人网站-构建进展-2026-10-30]]，本篇只记这一轮内容与定位上的改动。

## 一、起点：为什么改

原版的视觉气质（纸张色、墨色衬线、暖橙强调）保留，问题出在内容逻辑：

- 主标语「让理解持续复利，让每个工具都更懂你」有理解门槛，且把重心放在工具上，第一次来的人会以为这是个连接各种 AI 的软件。
- 五个栏目混用四套分类标准——「开始理解」是读者阶段，「构建方法／构建现场」是内容形式，「公开上下文」是公开范围，「前沿·思考·阅读」又装了好几个主题。同一篇文章经常不知道放哪儿。
- 首页先讲「为什么上下文重要」，再用几组不同名称反复引导同一批文章；大幅工具连接图占住首屏，但读者看不出背后是个什么样的人。
- 与 [[AI 账号定位]] 里写的目标不一致：主线是记录自己的积累与成长，帮新手建立个人上下文只是一个分支。

结论：主体应当是本人的阅读、思考、实践与变化；教程是一条清晰的新手路线，不是全站定位。

## 二、改了什么

| 位置 | 之前 | 现在 | 为什么 |
|---|---|---|---|
| 首页主张 | 让理解持续复利 | 把读过的、想过的、做过的，慢慢用起来。 | 具体，不解释也能懂；复利一说移到关于页 |
| 导航 | 首页／探索内容／关于此站 | 首页／从这里开始／全部内容／关于我 | 四项，先问「有什么」再问「我是谁」 |
| 栏目 | 5 个混用标准的栏目 | 3 个主题 + 5 个类型标签 | 主题管「讲什么」，类型管「怎么写」 |
| 首页顺序 | 理念 → 图 → 五栏目 → 更新 | 一句说明 → 案例 → 三主题 → 更新 → 订阅 | 先给判断依据，再给入口 |
| 首屏插图 | 工具连接示意图 | 阅读笔记引用卡片 | 让文字本人出场，替代抽象示意 |

三个主题：**个人积累**（怎么记录、整理、回看）、**AI 协作实践**（一个任务怎么完成、结果与局限）、**阅读与思考**（书里的观点与经历怎么相遇）。

五个类型标签：入门指南、实践记录、公开样本、阅读笔记、思考笔记。在「全部内容」里与主题**组合筛选**，不再各占一个大栏目。

首页案例区固定为三段式：**当时的问题 → 我的尝试 → 结果与局限**，并标注「公开演示案例 · 待真实材料替换」。

新增「从这里开始」页：一个熟悉的问题 → 一个实际例子 → 一个可以尝试的小步骤，只选三篇，读完给一条下一步建议。

文章页开头补「这篇适合……」，按类型给不同读者提示；订阅只留首页与文末，关于页不重复。

## 四、验证结果

- 1440 与 390 视口逐页检查首页、从这里开始、全部内容、文章、关于我：`document.scrollWidth` 均等于视口宽，无横向溢出。
- 导航高亮、主题＋类型组合筛选、搜索命中与高亮、文章目录与阅读进度、订阅邮箱校验、未知路由提示均正常，控制台无报错。
- 手机端修了三处：主题卡的「X 篇公开示例」被挤成两行两列、最近更新序号没对齐标题首行、入门路线标题贴住右边缘。
- 没做真实手机、微信内置浏览器、多浏览器测试。

## 五、踩过的坑

- **Chrome 的 `--window-size=390` 不等于手机视口**。不加移动仿真截出来的图会误导，让人以为右侧文字被裁。判断溢出只认 CDP 的 `Emulation.setDeviceMetricsOverride` 加 `scrollWidth === innerWidth`。
- **本地静态服务会被会话回收**。后台 `python3 -m http.server` 退出码 143 是进程被终止，不是页面报错；重跑一条命令即可，文件不受影响。
- **8766 端口被代理占了**，请求返回 502 而不是拒绝连接，换端口（用 8790）就好。
- 本机所有 TCP 走本地代理，**不能靠连通性判断端口是否开放**，必须看真实 HTTP 响应。
