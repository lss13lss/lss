# 个人网站部署通道（HTTP 上传口）

## 为什么需要它

本机到服务器的 SSH 走不通（2026-11-03 复测：22 端口握手后即被切断，443 端口同样超时），因此无法用 `scp`/`rsync` 直接改站点。此前每次发版都要本人在腾讯云网页终端手工上传 zip。

2026-11-03 在 Nginx 上开了一个带密钥的 HTTP 写入接口，作为**唯一自动部署通道**。它只复用已放行的 8080 端口，不新增端口、不改防火墙、不动 SSH。

## 怎么用

```bash
TOKEN=$(cat ~/.workbuddy/secrets/site-upload-token)
curl -X PUT -H "X-Upload-Token: $TOKEN" \
     --data-binary @本地文件 \
     http://122.51.126.188:8080/_up_/远端路径
```

返回值：`201` 新建、`204` 覆盖成功、`403` 密钥错误、`413` 超过 200MB。

删除远端文件：

```bash
curl -X DELETE -H "X-Upload-Token: $TOKEN" http://122.51.126.188:8080/_up_/<路径>
```

密钥不写入本仓库，本机存于 `~/.workbuddy/secrets/site-upload-token`（权限 600），服务器侧写在 `/etc/nginx/conf.d/site.conf`。

## 服务器侧实现

`site.conf` 的 `listen 8080` server 块内注入：

```nginx
location /_up_/ {
    if ($http_x_upload_token != "<token>") { return 403; }
    alias /var/www/site/;
    dav_methods PUT DELETE MKCOL;
    create_full_put_path on;
    dav_access user:rw group:rw;
    client_max_body_size 200m;
}
```

配套改动：

- 原配置备份在 `/etc/nginx/conf.d/site.conf.bak`
- `/var/www/site` 属主由 `ubuntu:ubuntu` 改为 `www-data:www-data`（Nginx 写入需要）
- 安装脚本 `/tmp/up.py`：幂等，`nginx -t` 通过才 reload，失败自动还原

## 验证（2026-11-03）

| 测试 | 结果 |
|---|---|
| 无密钥 PUT | 403 |
| 带密钥 PUT | 201 |
| HTTP 读回 | 内容一致 |
| DELETE | 204 |

同日首次实战：V3 前端 8 个文件 + 三篇稿件全部上传，本地与线上逐字节比对一致。

## 边界与风险

- **只能写 `/var/www/site`，不能执行命令。** 改 Nginx 配置、装软件、看日志仍需腾讯云网页终端，或让本人代跑。这一点没变。
- 密钥以明文随 HTTP 传输，同一链路可被嗅探。后果限于他人可篡改公开网页内容（站点内容本就公开），不涉及服务器权限。
- 撤销方式：`sudo cp /etc/nginx/conf.d/site.conf.bak /etc/nginx/conf.d/site.conf && sudo systemctl reload nginx`。
