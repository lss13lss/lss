## 一、问题到底在哪

先把「不好看」拆开，因为换工具未必能解决：

- **配色**：现在的图用的是正文同一套米白底、墨色字、朱红点缀。作为「页面里的装饰」很协调，但作为「论证用的插图」就跳不出来，读者容易当成版式纹样而不是信息。
- **信息密度**：三张图都在一个画面里讲了多个步骤和分支（尤其 `agent-loop-steps.svg`），字偏小、层级偏平，扫一眼抓不住重点。
- **不是 SVG 的问题**：SVG 无限缩放清晰、纯文本可进 Git、加载快、无外链图床，这些恰好都是本站要的。

**判断**：主要短板是配色与信息密度，不是工具。换工具能改善「画起来省不省事」和「风格感」，但只有重画才能真正变直观。

## 二、调研到的工具（2026-11-05 网上检索）

| 工具 | 类型 | 适合 | 对本站的短板 |
|---|---|---|---|
| **手写 SVG**（已选） | 代码即图 | 零依赖、可 Git 追踪、无限缩放、加载快、可精确控制 | 画复杂图示费时 |
| **Excalidraw** | 手绘风白板 | 教学感、直观、低门槛，导出 PNG/SVG | 手绘风与本刊克制排版要重新调和；复杂图仍需人工排 |
| **draw.io / diagrams.net** | 免费开源、精确控位 | 正式流程图／架构图，中文界面，导出 SVG/PNG/PDF/XML | 偏工程图，成品较「硬」，需自己定配色 |
| **Mermaid / D2** | 图表即代码 | 流程、时序、状态图；Markdown/Git 友好，长期好维护 | 样式定制受限，对「亮眼」帮助有限；D2 生态比 Mermaid 小 |
| **Napkin AI** | 文字转图解 | 最快把一段文字变成图解／信息图 | 免费版 PNG/PDF 可导，SVG/PPT 与去水印需付费；界面偏英文；生成结果要人工核对准确性 |
| **Canva 可画** | 中文一站式设计 | 亮眼封面、信息图、模板多，国内可用 | 偏通用设计工具；SVG 导出有限制，多为 PNG |
| **ProcessOn / 畅图AI** | 国内中文在线作图 | 中文模板、协作、AI 生成，网络与支付友好 | 免费额度与导出限制需确认；成品可能带平台痕迹 |
| **Whimsical** | 轻量高颜值白板 | 流程图／脑图，视觉舒服 | 英文界面为主，国内访问一般 |

> 产品能力与收费会变，上表是 11-05 的检索结论，实际选用前请再确认一次导出格式与水印规则。

## 三、三条可走的路线

1. **不换工具，只重画（推荐先试）**：仍是手写 SVG，但换一套高对比配色、每张图只讲一件事、加大字号、少字多图形。好处是零新增依赖、部署通道不变、Git 可追踪、移动端清晰；一次只改一篇，风险最小。
2. **换手绘感**：用 Excalidraw 画，导出 SVG 放进 `assets/`。更直观、更有人味，适合入门讲解，但要重新定风格以贴合刊物调性。
3. **换正式图示**：用 draw.io（或 Mermaid／D2 生成）画流程与分层图，导出 SVG。适合「AI → LLM → 对话产品 → Agent」这类分层图与「一轮四步」这类循环图。

Napkin AI / Canva 可画 更适合快速出封面或信息图，作为备选；生成内容需人工核对，不建议直接进正文当论证图。

## 四、硬约束（换工具也要守）

- 站点是静态 SPA，无构建步骤；图片放进 `assets/` 后仍走 [[03-项目/个人项目/个人网站-部署通道-2026-11-03|HTTP 上传口]] 发版。
- 不用外链图床，图片随仓库可追踪；优先 SVG，PNG 需考虑体积与高分屏。
- 移动端 `article-figure img` 有 `min-width: 600px` 横滑与「点开看大图」，宽图仍要能读。
- 面向中国大陆公众访问，工具与素材加载不能依赖境外 CDN。
- 一张图只服务一个论点；图注与 `alt` 要写清，且会进搜索全文。
