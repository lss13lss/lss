# vault_check

整理知识库后用来自查的小脚本。一次跑完「链接」和「库卫生」两类检查。

## 用法

```bash
python3 tools/vault_check/check_links.py            # 链接 + 卫生，全量自查
python3 tools/vault_check/check_links.py --links     # 只查死链
python3 tools/vault_check/check_links.py --junk      # 只查库卫生
python3 tools/vault_check/check_links.py --path DIR  # 指定其他库路径
```

退出码：有死链返回 `1`，仅卫生问题返回 `0`（卫生问题不该阻塞同步）。

## 一、失效 wikilink

按 Obsidian 的解析规则匹配：

- `[[名称]]` 匹配任意位置的同名文件（含附件，忽略大小写）
- `[[路径/名称]]` 精确匹配，或退回 basename 匹配
- `[[名称|别名]]`、`[[名称#标题]]` 取前半部分
- `[[文件夹]]` 单独归为「指向文件夹的链接」——Obsidian 里不可点击，属于需要修的一类

跳过 `.git`、`.obsidian`、`.trash`；`backups`、`tools`、`skills` 只作为链接目标被索引，不扫描其内部链接。

> 输出里若出现 `[[笔记名]]`、`[[另一篇笔记#^目标段落|目标段落摘要]]` 这类，是文档中刻意写的语法示例，可忽略。

## 二、库卫生检查

| 检查项 | 说明 |
|---|---|
| 孤儿附件 | `attachments/` 中没有任何笔记引用的图片 |
| 构建产物 / 系统垃圾 | `.venv`、`venv`、`__pycache__`、`.pytest_cache`、`.mypy_cache`、`.ruff_cache`、`*.egg-info`、`node_modules`；`.DS_Store`、`._*`、`*.bak`、`*.swp`、`*.tmp`、`*.pyc` |
| 空目录 | 提示项，不计入问题（多为设计上保留的分类占位） |
| 零字节笔记 | 空 `.md`，多为未写完就放下的草稿 |
| 重复笔记 | 内容完全相同的 `.md`（按内容哈希比对） |

## 三、整理时的注意事项

- **删除前先备份**。被 Git 跟踪的文件可从历史取回，但未跟踪的（虚拟环境、`.bak`、生成产物、日志）删掉就没了，要先打包留档。流程见 [[AGENTS|AGENTS.md]]。
- **删除笔记前先确认它引用的图片是否需要迁走**。图片文件不会跟着笔记一起消失，会变成孤儿文件——文件还在，但没有任何笔记指向它。
- **构建产物不要同步**。虚拟环境里写死了本机绝对路径，跨系统（Mac ↔ Windows）同步过去只会得到一个跑不起来的环境；用 `.gitignore` 挡住，需要时在目标设备重建。
- 整理完成后建议按此顺序收尾：跑本脚本 → 修正死链 → 提交 → 推送到远端 → 在 [[00-整理记录-2026-09-21]] 里补一段记录。
