## 预训练
预训练：在大规模无标注文本数据上进行模型的训练，目标是让模型学习自然语言的基础表达、上下文信息和语义知识，为后续任务提供一个通用的、丰富的语言表示基础。

## 微调
微调：微调是通过在特定任务的数据上进一步训练预训练模型来优化其性能。在预训练模型的基础上，可以根据特定的下游任务对模型进行微调。
提示校准：旨在通过调整提示的措辞、结构或内容来减少模型输出中的偏见。
LoRA：通过低秩分解减少微调过程中需要更新的参数数量。LoRA 的核心思想是在预训练模型的每一层中引入可学习的低秩矩阵，从而替代全参数更新。对于预训练模型中的权重矩阵 W，LoRA 将其分解为两个低秩矩阵 A 和 B，即 W=W+ΔW，其中 ΔW=A×B。矩阵 A 和 B 的秩通常较低（如 1 或 2），因此参数量大大减少。参数更新​​：在微调过程中，只更新低秩矩阵 A 和 B，而保持预训练权重 W 不变。这种方法显著减少了需要训练的参数数量。

## 推理
幻觉：1.训练数据的局限性 大模型的知识和行为主要来源于训练数据，而训练数据的局限性是幻觉产生的根本原因之一。2. ​模型的生成机制 大模型是基于概率分布生成文本的，这种生成机制本身可能导致幻觉：模型在训练时通过最大化语言模型的似然函数来学习数据分布，但这并不意味着模型能够“理解”知识的真实性。3. ​​训练目标的局限性​
缓解幻觉：​引入外部知识库、微调与领域适配、后处理与校验、不确定性估计
涌现：是指当模型规模（如参数量、训练数据量或计算资源）达到一定阈值时，模型突然表现出一些在小规模模型中不存在的能力。
数据增强：数据增强是通过生成更多的训练数据来提高模型的鲁棒性和泛化能力。
LLM复读机：表现：词、短语、段落。原因：1.训练数据的特性、2.自注意力机制的局限性长序列生成中，模型可能会过度依赖某些高频模式，而忽略低频但更有意义的表达。3.大模型通过最大化语言模型的似然函数来学习数据分布。这种目标倾向于优化高频模式，而对低频模式的优化不足。4.缺乏外部知识或记忆
解决：1.引入记忆机制、2.引入多样性目标、3.解码阶段的改进：​温度调节，Top-k 和 Top-p 采样，长度惩罚，多样性惩罚：对重复的 n-gram 赋予较低的权重，避免生成重复内容。
n-gram 过滤：用于检测和移除文本中的重复 n-gram（如词、短语或句子）。它通过记录已经生成的 n-gram，并在后续生成过程中避免重复使用这些 n-gram，从而提高文本的多样性。
### 解码策略
Batch Normalization（纵向规范化）：针对单个神经元进行，利用网络训练时一个 mini-batch 的数据来计算该神经元xi的均值和方差,因而称为 Batch Normalization。Batch Norm通过对一个批次（batch）内的数据进行归一化，使得每个特征的均值为0，方差为1。Batch Norm依赖于批次内样本的统计量（均值和方差），而变长序列会导致不同样本的特征维度不一致，难以有效计算批次统计量。
Layer Normalization（横向规范化）：综合考虑一层所有维度的输入，计算该层的平均输入值和输入方差，然后用同一个规范化操作来转换各个维度的输入。Transformer解决的是序列问题，一个存在的问题是不同样本的序列长度不一致，而Batch Normalization需要对不同样本的同一位置特征进行标准化处理，所以无法应用；当然，输入的序列都要做padding补齐操作，但是补齐的位置填充的都是0，这些位置都是无意义的，此时的标准化也就没有意义了。
Transformer模型通常需要处理长序列，Layer Norm可以在每个样本内部独立进行，便于并行计算，而Batch Norm需要在整个批次上进行统计，可能增加内存开销和计算复杂度。
RMSnorm：均值为0的LN，1. ​​计算效率更高​。2. ​​数值稳定性更好​3. ​​更适合大规模模型​4. ​​与自注意力机制的兼容性​。Layer Norm需要计算均值和方差，而RMSNorm仅需要计算均方根减少了计算步骤，尤其在处理大规模模型时，能够显著提升计算效率。
Deep Norm：的主要思想是在网络的每一层之间插入归一化层，以减小输入数据的分布差异，从而加速收敛并提高模型的泛化能力。与传统的批归一化（Batch Normalization）不同，Deep Norm 在每一层都进行归一化，而不是仅在特定层进行。

### 推理性能
梯度裁剪：梯度裁剪是一种用于防止梯度爆炸的优化技术，主要用于训练深度学习模型时的稳定性控制。
KL散度：用于衡量两个概率分布之间的差异，在语言模型中，KL 散度用于衡量预测分布 Q(w) 和真实分布 P(w) 的差异。 KL散度是一种用于衡量两个分布之间差异的指标，交叉熵损失函数是KL散度的一种特殊形式。在二分类问题中，交叉熵函数只有一项，而在多分类问题中有多项。
交叉熵损失函数：模型预测分布与真实分布之间的信息损失，损失值越小，说明模型的预测越接近真实分布。，交叉熵损失函数更适合分类问题，而MSE损失函数更适合回归问题。

准确率：正确预测的样本数占总样本数的比例。精确率：在所有被预测为正类的样本中，实际为正类的比例。召回率：在所有实际为正类的样本中，被正确预测为正类的比例。F1分数：精确率和召回率的调和平均数，综合考虑两者的平衡。
提示学习（Prompt Learning）：Prefix Tuning旨在通过在输入序列前添加可学习的“前缀”标记，以引导预训练语言模型完成特定任务。参数高效​​：只需更新少量的前缀参数，大幅减少了需要微调的参数数量。任务适应性强​​：适用于多种下游任务，如文本分类、问答系统等。易于实现​​：与标准的微调方法相比，Prefix Tuning 的实现相对简单。
Prompt Tuning在输入序列的适当位置插入一组可学习的虚拟标记（prompt tokens），这些标记与原始输入拼接后一起输入到模型中。提示标记可以插入到输入序列的不同位置，以适应不同的任务需求。
P-Tuning：P-Tuning 使用连续的向量作为提示，这些向量通过训练得到。将连续提示向量与原始输入的嵌入进行拼接，然后输入到模型中。P-Tuning v2：P-Tuning v2 引入了多层次的提示机制，不仅在输入层添加提示，还在模型的中间层引入提示，增强模型的任务适应性。
Prefix Decoder（前缀解码器）：它通过在解码过程中动态调整输入序列的前缀，以更好地捕捉上下文信息，从而提高生成质量。在每一步生成时，Prefix Decoder会根据已生成的部分动态调整输入序列的前缀，确保解码器能够利用最新的上下文信息。通过不断更新输入前缀，Prefix Decoder能够更准确地理解当前生成位置所需的上下文信息，减少信息遗漏或误解。
Causal Decoder（因果解码器）：在每一步生成时，Causal Decoder只使用当前位置及之前的位置的信息，避免未来信息的影响。

IVF（倒排文件索引，Inverted File Index）​：​​聚类​​：使用K-means等聚类算法将整个数据集划分为 C 个簇，每个簇有一个代表点（聚类中心）。分配​​：将每个数据点分配到最近的聚类中心，形成倒排表（Inverted List），即每个聚类中心对应一个包含属于该簇的所有数据点的列表。​​搜索​​：对于查询点，首先找到其最近的若干个聚类中心（称为粗粒度搜索）。然后在这些聚类对应的倒排表中进行细粒度搜索，寻找最近邻。
PQ（乘积量化，Product Quantization）​：​​向量分解​​：将 D 维向量分解为 m 个子向量，每个子向量的维度为 D/m。量化​​：对每个子向量空间分别构建量化器（通常使用K-means聚类），将每个子向量映射到最近的聚类中心（码字）。编码​​：将所有子向量的码字组合起来，形成整个向量的压缩表示（乘积码本）。搜索​​：对查询向量进行同样的分解和量化。计算查询向量与数据向量在量化空间中的距离（通常使用残差距离）。通过遍历部分或全部量化组合，寻找近似最近邻。
HNSW（分层可导航小世界图，Hierarchical Navigable Small World Graphs）：HNSW 是一种基于图的索引结构，通过构建多层小世界图来实现高效的近似最近邻搜索。其主要特点包括：分层结构​​：索引由多个层级组成，底层包含所有数据点，上层通过选择部分节点形成更小的图，逐层向上直到顶层只有一个节点。小世界特性​​：每个节点在图中与少量其他节点相连，但由于分层结构，任意两个节点之间可以通过较少的跳数连接。导航搜索​​：从顶层开始搜索，逐步向下层导航，利用节点间的连接关系快速逼近查询点的最近邻。在每一层，通过贪心算法选择与查询点距离最近的节点，直到达到底层或满足精度要求。
k-means：​​无监督学习算法​​，主要用于将数据集划分为 ​​K​​ 个不同的簇（clusters），使得同一簇内的数据点相似度较高，而不同簇之间的数据点相似度较低。

2 Self-RAG：如何让 大模型 对 召回结果 进行筛选？经典的RAG架构中（包括KG进行上下文增强），对召回的上下文无差别地与query进行合并，然后访问大模型输出应答。但有时召回的上下文可能与query无关或者矛盾，此时就应舍弃这个上下文，尤其当大模型上下文窗口较小时非常必要（目前4k的窗口比较常见）。
Self-RAG 的重要创新：Reflection tokens (反思字符)。通过生成反思字符这一特殊标记来检查输出。这些字符会分为 Retrieve 和 Critique 两种类型，会标示：检查是否有检索的必要，完成检索后检查输出的相关性、完整性、检索片段是否支持输出的观点。模型会基于原有词库和反思字段来生成下一个 token。
Graph RAG：种基于知识图谱的检索增强技术，通过构建图模型的知识表达，将实体和关系之间的联系用图的形式进行展示，然后利用大语言模型 LLM进行检索增强。Graph RAG将知识图谱等价于一个超大规模的词汇表，而实体和关系则对应于单词。通过这种方式，Graph RAG 在检索时能够将实体和关系作为单元进行联合建模。Graph RAG 思想：对用户输入的query提取实体，然后构造子图形成上下文，最后送入大模型完成生成

ROUGE (Recall-Oriented Understudy for Gisting Evaluation)​ROUGE 是一种基于 n-gram 重叠的指标，主要用于评估自动生成的摘要与参考摘要的相似性。它更注重召回率（Recall），即模型输出中覆盖了多少参考摘要的内容。
METEOR (Metric for Evaluation of Translation with Explicit ORdering)​METEOR 是一种改进的翻译评价指标，除了 n-gram 匹配外，还考虑了同义词、词干、词序和语义相似性。它通过引入语义匹配因子来提高评价的准确性。
TER (Translation Edit Rate)​衡量将机器翻译输出修改为参考翻译所需的最小编辑操作次数。
3 使用大模型进行评估 通过构造 Prompt Engineering 让大模型充当一个评估者的角色，从而替代人工评估的评估员；同时大模型可以给出类似于人工评估的结果，因此可以采取人工评估中的多维度量化评估的方式，实现快速全面的评估。
拆分评估维度。如果评估维度太多，模型可能会出现错误格式导致返回无法解析，可以考虑将待评估的多个维度拆分，每个维度调用一次大模型进行评估，最后得到统一结果；
合并评估维度。如果评估维度太细，模型可能无法正确理解以至于评估不正确，可以考虑将待评估的多个维度合并，例如，将逻辑性、通顺性、智能性合并为智能性等；
提供详细的评估规范。如果没有评估规范，模型很难给出理想的评估结果。可以考虑给出详细、具体的评估规范，从而提升模型的评估能力；
提供少量示例。模型可能难以理解评估规范，此时可以给出少量评估的示例，供模型参考以实现正确评估。

评估并优化生成部分
1. 提升直观回答质量，构造Bad Case，修改prompt要求其回答具体，去掉多余部分，如果答案比较长，请酌情进行分段，以提高答案的阅读体验。如果答案有几点，你应该分点标号回答，让答案清晰具体
2. 标明知识来源，提高可信度，由于大模型存在幻觉问题，有时我们会怀疑模型回答并非源于已有知识库内容，这对一些需要保证真实性的场景来说尤为重要，
3. 构造思维链，可以通过构造思维链，将 Prompt 构造成一系列步骤来尽量减少其能力限制，例如，我们可以构造一个两步的思维链，要求模型在第二步做出反思，以尽可能消除大模型的幻觉问题。
4. 增加一个指令解析，在我们的检索 LLM 之前，增加一层 LLM 来实现指令的解析，将用户问题的格式要求和问题内容拆分开来。
这样的思路其实就是目前大火的 Agent 机制的雏形，即针对用户指令，设置一个 LLM（即 Agent）来理解指令，判断指令需要执行什么工具，再针对性调用需要执行的工具，其中每一个工具可以是基于不同 Prompt Engineering 的 LLM，也可以是例如数据库、API 等。
评估并优化检索部分
1.评估检索效果：
有的 query 可能需要联合多个知识片段才能做出回答，对于这种 query，我们如何评估？
检索到的知识片段彼此之间的顺序其实会对大模型的生成带来影响，我们是否应该将检索片段的排序纳入考虑？
除去检索到正确的知识片段之外，我们的系统还应尽量避免检索到错误的、误导性知识片段，否则大模型的生成结果很可能被错误片段误导。我们是否应当将检索到的错误片段纳入指标计算？
2.优化检索的思路
1. 知识片段被割裂导致答案丢失，优化文本切割方式，针对性构建更合适的分割规则，也可以考虑训练一个专用于文本分割的模型，来实现根据语义和主题的 chunk 切分。
2. query 提问需要长上下文概括回答，优化知识库构建方式。针对可能需要此类回答的文档，我们可以增加一个步骤，通过使用 LLM 来对长文档进行概括总结，或者预设提问让 LLM 做出回答，从而将此类问题的可能答案预先填入知识库作为单独的 chunk，来一定程度解决该问题。
3. 关键词误导，源于 query 中有多个关键词，其中次要关键词的匹配效果影响了主要关键词。一般优化思路是，对用户 query 进行改写，这也是目前很多大模型应用的常用思路。即对于用户输入 query，我们首先通过 LLM 来将用户 query 改写成一种合理的形式，去除次要关键词以及可能出现的错字、漏字的影响。具体改写成什么形式根据具体业务而定，可以要求 LLM 对 query 进行提炼形成 Json 对象，也可以要求 LLM 对 query 进行扩写等。
4. 匹配关系不合理，匹配到的强相关文本段并没有包含答案文本。该问题的核心问题在于，我们使用的向量模型和我们一开始的假设不符。很多向量模型其实构建的是“配对”的语义相似度而非“因果”的语义相似度，例如对于 query-“今天天气怎么样”，会认为“我想知道今天天气”的相关性比“天气不错”更高。

二级检索策略：关键信息提取、原始文本处理优化
1、混合检索+重排序
一级检索：使用多路召回（如向量检索 + BM25关键词检索），分别获取候选文档集。
结果合并：按相关性分数加权合并（如向量检索占70%、BM25占30%），保留 Top-N 结果（如 Top-200）。
二级重排序：使用轻量级重排序模型（如 Cohere Rerank、ColBERT）对合并结果重新评分，筛选 Top-K（如 Top-5）最终结果。
案例：金融问答系统：一级检索使用 FAISS 向量库 + Elasticsearch BM25，二级重排序采用 ColBERT 交叉编码器，召回率提升 18%。
关键点：重排序模型需权衡精度与延迟（ColBERT 精度高但延迟较高，Cohere Rerank 为 API 调用更便捷）。合并策略需根据领域数据调整权重（如医疗领域更依赖语义，向量检索权重可提升至 80%）。
2、元数据过滤增强检索
元数据标注：在文档分块时提取关键信息（如时间、作者、文档类型）并存储为元数据。
一级检索：通过向量/关键词检索获取粗粒度候选集。
二级过滤：根据用户查询解析出的元数据条件（如 "2023年后的政策文件"）筛选结果。
案例：法律文书检索：一级检索召回 Top-100 结果，二级过滤按 "法院层级=最高法院" 缩小范围，准确率提升 25%。
关键点：需设计结构化元数据字段（如时间、来源、标签），并与业务场景强关联。支持动态条件解析（如从查询中提取 "近三年" 并转换为 publish_year >= 2021）。
3、HyDE（Hypothetical Document Embeddings）假设文档生成
生成假设文档：利用 LLM 根据用户查询生成假设性答案或扩展描述。
二级检索：将假设文档与原查询同时编码为向量，加权融合后检索。
关键点：需控制生成文本的多样性（温度参数调低）以避免偏离原意图。可结合 RAGAS 评估工具量化 HyDE 对召回率的影响。
4、分块重组与上下文填充（Chunk Fusion）
重叠分块：使用滑动窗口对文档分块（如 512 tokens，重叠率 15%）。
二级重组：对一级检索到的相邻分块合并，重构完整上下文。
关键点：分块策略需与文档类型匹配（论文需按章节分块，代码按函数分块）。动态控制合并后的最大长度（避免超出 LLM 上下文窗口）。
5、知识图谱引导检索（Knowledge Graph Enhancement）
实体链接：从查询中提取实体（如人名、地点），链接到知识图谱（如 Wikidata）。
路径扩展：根据图谱关系扩展查询（如 "马斯克" → "特斯拉、SpaceX"）。
二级检索：用扩展后的查询重新检索。
关键点：依赖高质量知识图谱与实体识别模型（如 spaCy NER）。适用于专业领域（医疗、金融）的术语扩展。

BM25：原理是根据查询词在文档中的出现频率以及查询词在整个文本集中的出现频率，来计算查询词和文档的相似度。它是对传统TF-IDF方法的改进，通过引入非线性词频处理、文档长度归一化和调整的逆文档频率，显著提升了检索效果。关键因素：词频（TF）的非线性饱和：避免高频词过度影响得分。文档长度归一化：调整长文档与短文档的得分偏差。逆文档频率（IDF）优化：提升区分性强的词项的权重。
FAISS：Meta（原Facebook）AI团队开发的高性能向量相似性搜索库，专为大规模向量数据的高效检索而设计。它广泛应用于推荐系统、图像/文本检索、语义搜索等场景，尤其擅长处理高维向量的快速近邻搜索（KNN）和聚类任务。支持多种距离度量（如L2距离、内积、余弦相似度）。兼容多种数据格式（如NumPy数组、PyTorch/TensorFlow张量）。
spaCy：1​​输入文本​​ → 2. ​​分词（Tokenizer）​​ → 3. ​​词性标注（Tagger）​​ → 4. ​​依存句法分析（Parser）​​ → 5. ​​命名实体识别（NER）​​ → 6. ​​输出 Doc 对象​.   1. ​​分词与词形还原​​分词器（Tokenizer）​​：基于语言规则与统计模型，将文本切分为 Token（词/符号），支持自定义分词规则。​​词形还原（Lemmatizer）​​：结合词典与上下文，将单词还原为基本形式（如 "running" → "run"）。
2. ​​词性标注与句法分析​​，​​词性标注器（Tagger）​​：利用统计模型预测每个 Token 的词性标签（如名词、动词）。依存解析器（Parser）​​：构建依存树，识别主谓宾等语法关系（如 "猫 追 老鼠" 中 "猫" 是主语）。
3. ​​命名实体识别（NER）​​基于预训练模型识别实体（如人名、地点），通过 doc.ents 提取结果，支持自定义实体类型扩展。
4. ​​语义表示​​词向量（Word Vectors）​​：集成预训练词向量（如 GloVe），支持语义相似度计算（token.similarity()）。语义角色标注（SRL）​​：识别谓语的语义角色（如施事者、受事者），需结合额外模型或规则。
Cohere rerank：​​语义重排序​​：基于 Transformer 架构，对初步检索结果（如 Top 100 候选文档）进行二次排序，解决传统关键词匹配（如 BM25）的“语义鸿沟”问题。支持 ​​4,096 个 Token 的上下文窗口​​，可处理长文本（如技术网页、法律合同）的细粒度匹配。混合检索优化​​：结合向量检索（语义相似度）与关键词检索（BM25），通过 ​​Reciprocal Rank Fusion (RRF)​​ 算法融合结果，提升召回率与精确度的平衡。
deepseek创新：​架构创新：混合专家（MoE）与动态路由​  ​​细粒度专家划分与共享专家分离​​传统MoE模型（如Mixtral）的专家划分粒度较粗（如每专家7B参数），而DeepSeek-V3将专家拆分为更细粒度（如每专家0.5B参数），总参数量达6710亿，但单Token仅激活370亿参数（占比5.5%），显著降低计算成本。
引入​​共享专家​​（处理通用任务）与​​路由专家​​（处理特定任务），通过动态偏置项调整路由倾向，解决负载不均衡问题，提升模型泛化能力。
