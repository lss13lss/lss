# TRAG
tRAG是一个检索增强生成（RAG）业务应用全生命周期管理平台。将RAG的功能接口进行整合，以中间件的形式提供给业务使用，帮助业务落地 RAG 应用。

## 结构

tRAG使用实例(instance)来管理资源和服务。作为基本使用单元，实例中包含了应用组信息、管理员、Token、命名空间(Namespace)、资源、策略、知识库、工具、长记忆等一系列能力，每种能力对应唯一code。用户一旦创建好实例，实例的所有能力均可通过 API + code进行调用。

### 实例(instance) 
实例通过token创建，每个实例对应一个ragCode,在创建namespace和collection等资源时使用ragCode绑定到实例，API提供了创建、删除、更新TRAG实例的接口，在python和java中可以使用ragCode和对应封装好的接口对实例进行管理。

### 命名空间（Namespace）
命名空间是对内存进行逻辑隔离的组织单位，类似于MySQL的数据库概念。一个tRAG实例下可以创建多个Namespace，而每个Namespace可以有多个Collection；使用时可以将测试环境和正式环境的数据分别放在不同的Namespace中，用来实现测试和生产隔离。

### 存储(Memory）
存储是RAG的基础能力，TRAG将知识库、Session、长记忆做了场景化封装在知识库场景，有向量、倒排、图三种存储类型，后续还会扩充其他存储类型。在会话管理场景下，提供Session、以及 Long-Term-Memory两个基础存储板块。

### 向量知识库Collection）

向量知识库，是以向量存储的知识库，使用时候无需关心底层集群细节，直接进行数据导入和检索即可。知识库的底层对应多个存储索引。在导入、检索、查询时根据sharding_key值不同路由到不同的底层存储索引。多个向量数据库，多个DB构成向量数据库集群，创建 Collection 时指定Index数量。写入和检索文档时必须指定ShardingKey, ShardingProxy使用ShardingKey通过一致性Hash映射匹配到Index。文档更新使用覆盖式导入。

### 图知识库（Graph）

图库可以理解为独立的图数据库，图库下中可以包含多个图索引，各个图索引间相互隔离。图索引包含两部分内容：图entity向量检索内容（在向量存储中）+ 子图。图检索召回时包含两步：1. 根据query 从图entity向量检索内容召回相关的 entity, 2. 根据召回的 entity 在子图中检索信息。文件上传使用COS实现。

### 会话（Session）

会话管理用于 rag 场景下与模型/Agent交互的历史会话提供存储服务。一个session 表示一组对话，比如用户和NPC，或者某个群聊。session创建时会绑定长记忆，保证session上施加长记忆的配置策略，用于在对话时根据策略调取长记忆进行文档召回。

### 长记忆（LongMemory）

长记忆旨在解决由于模型上下文（context）限制所导致的记忆遗忘问题。长记忆，包含了实例，资源，以及多种策略组合。 使用长记忆可以自动生成用户的记忆摘要，偏好习惯，并在后续的对话中予以引用。

实现流程：首先创建session，用户发起对话时生成query，读取记忆后进行prompt拼接得到response。后续将聊天记录保存到session中，进行会话管理并构建长记忆，对会话记录进行摘要提取（聊天记录摘要：一个session对应多个子会话，一个子会话对应一条摘要）和画像提取（画像记忆：姓名，年龄，爱好等）在生成用户query后读取记忆时使用API召回长记忆，设定长记忆触发机制（轮次触发、时间触发、关键字触发）。
1. 按照轮数触发（推荐使用）
每次拉取最新的N轮对话，进行长记忆的总结更新。例如：触发策略设置为20轮，当历史对话累积到20，40轮等都会拉取最近的20轮进行总结。（注意这里一问一答表示两轮）
2. 按时间定时触发
每次拉取最近一段时间的对话，进行长记忆的总结更新。例如：触发策略设置为3分钟，每隔3分钟会拉取这段时间内的对话进行总结。

### 资源

资源（Resource）是 tRAG 对可扩展能力做的一种抽象，目前 tRAG 内有 3 种资源类型：
模型资源：对应 VENUS 模型服务所提供的能力，或代理的其他商业模型能力，包括混元模型api。
策略资源：本质是一组 json 配置，用于排序、召回、长记忆等特定场景，通过策略来控制业务的个性化配置。
插件资源：该资源是 插件/工具（plugin/tool）的绑定，表示某个实例有该 tools 的调用权限；tools 的所有权是归属到tools开发者的，由开发者来控制tools的权限、版本和后续代码维护。


## 测试API接口

TRAG的API接口分类与TRAG结构基本一致，除了与实例相关的功能接口外还新增了一些针对业务特定功能的支持接口。对接口进行测试主要通过Swagger和Stoplight，后期为了整理方便使用Postman进行测试。

### Resource

资源类型包括：Embedding、Rerank、Rewrite、Summary、Policy、Tools、llm
提供了list，get，create，delete，update，bind，unbind等接口，使用ragCode和namespaceCode与实例和命名空间进行关联管理实现创建删除绑定等操作。

### Collection

核心操作：导入/删除/检索document
提供了embedding，query，similarity，delete，list等接口，collection绑定到namespace，同时通过collectuon来管理resource；可以通过API在一个namespace下创建多个collection，也可以在collection中创建和管理资源，计算embedding计算，检索向量，计算相似度等。

### Session

核心操作：创建/删除session，更新
session通过namespace创建并管理，session中包含了用户的信息和会话的拓展信息，可以通过session清空所有的memory但不可以直接通过session具体操作和查看memory。

### memory

对话的记忆，依托于session，同时包含了对话的具体信息（request，respond，remark）一条request加一条respond记为两条信息。可以通过sessionId获取指定区间的memory。


## Python SDK调用TRAG

使用python可以调用TRAG的各种功能实现知识库全流程操作。需要安装配置环境。
具体操作过程：
1.使用ragtoken在instance中创建namespace，获取namespaceCode用与管理namespace。
2.创建collection，在collection中引入文档，可以使用策略进行导入（策略中定义了加载、分片、embedding的方法）也可以自定义策略进行导入。导入文档后可以使用collection的search_documents功能对文档进行检索测试。
3.创建agent，agent内包含了llm和tools资源，在处理输入时调度资源进行回答。
4.集成知识库，创建retriever，对question进行知识库检索，召回的文档和question一起输入agent，大模型基于知识库片段对question进行回答。

使用python调用TRAG时大多基于code实现对API的调用，methods中定义了默认值。
优点：调用简单，
缺点：参数不透明，调用时传入的参数与API参数有区别，如API需要参数为Embedding,python定义的参数类型为embedding，且python中相对于API缺少部分功能。
