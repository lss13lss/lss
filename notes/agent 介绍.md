# agent 介绍
# 引论
## 预测性ai到自主代理
从处理被动的，离散的任务的预测或创建内容的ai，要转型到自主解决问题和执行任务的新型“软件”
他是一个完整的，能够制定计划并采取行动来实现的应用程序。
他结合了LLM的推理能力和实践的能力，使其能够处理模型本身不能实现的复杂的多步骤的任务。
代理可以自主工作，不需要人每次干预和引导
代理的三部分：模型，工具，编排层
能力分类：简单的，连接型的；复杂的，协作式多代理系统。
架构设计：每个部分的设计实现细节
构建生产环境：评估，运维，安全等。

我的理解：agent是一个由一个或多个不同类型的模型以及各种工具构成的集合体，能够将复杂任务拆解并分配给对应的模型和工具进行执行。中央由一个大模型进行决策和调度。
# 简介
agent可以定义为模型，工具，编排层和运行时服务的组合
- 模型（大脑）：处理信息，评估，决策
- 工具 ：连接外部世界，执行操作和收集外部信息到上下文中
- 编排层：处理规划，记忆和推理策略执行。将复杂目标分解，决定何时思考，何时实用工具
- 部署：生产环境的部署
agent是管理llm输入以完成工作的软件。对于任何一次调用我们都会输入指令、事实、可调用工具、实例、会话历史、用户资料等。在上下文窗口填充恰到好处的信息以获得我们想要的输出。
本质上讲agent是一个致力于上下文窗口策划艺术的系统，是一个无休止的循环：组装上下文、提示模型、观察结果，然后为下一步重新组装上下文。 上下文可能包括系统指令、用户输入、会话历史、长期记忆、来自权威来源的接地知识、可以使用哪些工具，以及已经调用的工具的结果。 这种对模型注意力的精密管理使其推理能力能够解决新颖的情况并达成目标。
## 代理式问题解决流程
五个基本步骤
- 获取任务 由一个具体的，高级的目标启动
- 扫描环境 agent感知环境获取上下文，编排层获取可用资源
- 深入思考 推理模型驱动的agent核心“思考”循环，分析任务并制定计划
- 采取行动 编排层执行计划中的第一个具体步骤，调用适当的工具
- 观察迭代 agent观察行动结果

## agent系统分类
五级代理系统：
- 0 核心推理系统
- 1 连接型问题解决者
- 2 战略型问题解决者
- 3 协作式多代理系统的兴起
- 4 自进化代理
### 0 核心推理系统
仅仅包含LLM，完全基于预训练知识对于问题作出相应
### 1 连接型问题解决者
通过连接并利用外部工具，不再局限于静态的，预训练的知识
这种与世界互动的基本能力——无论是使用搜索工具获取比分、使用金融 API 获取实时股票价格，还是通过检索增强生成（RAG）访问数据库——是第 1 级代理的核心能力。
### 2 战略型问题解决者
随着上下文工程的出现，能力得到显著提升，能够战略性的规划复杂的多部分的目标
代理的准确性取决于专注且高质量的上下文。上下文工程策划模型的有限注意力，以防止过载并确保高效性能
### 3 协作式多代理系统的兴起
多agent协同，agent将其他agent视为工具，通过为其他agent创建任务来采取行动。
### 4 自进化代理
agnet系统可以识别自身能力的差距，并动态创建新工具甚至新agnet来填补这些差距
从使用固定资源转向积极扩展资源
## 核心代理架构：模型、工具与编排
### LLM 大脑
模型的选择不能仅以基准测试分数为标准，应该具备处理复杂的、多步骤问题的卓越推理能力，以及与世界互动的可靠工具使用能力。
首先要定义业务问题，根据直接对应于该结果的指标测试模型。
可以选择多个模型来组成一个团队，根据能力和特点进行分工。模型的router可以使自动的也可以是硬编码的，但是这会影响优化性能和成本。
### 工具
允许agent超越其静态训练数据，以获取实时信息并在世界中采取行动。一个强大的工具接口是一个三部分的循环：定义工具能做什么、调用它并观察结果。
几种主要的工具类型：
#### 检索信息
访问最新信息的能力。
RAG查询向量数据库，对于结构化数据，自然语言转 SQL
#### 执行动作
通过将现有的 API 和代码函数包装为工具。对于更动态的任务，代理可以即时编写并执行代码
#### 函数调用
为了让代理可靠地进行“函数调用”并使用工具，它需要清晰的指令、安全连接和编排。
给代理一份结构化契约，描述工具的用途、所需参数及其预期响应。
### 编排层
决定模型何时应进行推理、哪个工具应采取行动，以及该行动的结果应如何影响接下来的行动。
#### 核心设计选择
确定agent的自主程度，需要再确定的，可预测的工作流和高自主性的决策之间进行权衡。
框架必须为可观察性而构建。当代理行为异常时，您不能简单地在模型的“思考”中设置断点。
#### 指令引导
系统提示词/核心指令，提供约束和身份定位
#### 上下文增强
短期记忆维护对话历史，根据当前的对话提供模型需要的即时时上下文
长期记忆提供跨会话的持久性
编排器赋予agent预取和主动查询自身历史的能力，使其能够“记住”用户的偏好或几周前类似任务的结果，从而获得真正个性化且持续的体验。
### 多系统模式
一个复杂的流程被分割为离散的子任务，每个子任务被分配给一个专门的、专注的 AI 代理。
对于动态或非线性任务，**协调器（Coordinator）**模式至关重要。它引入了一个“经理”代理，负责分析复杂请求，分割主要任务，并智能地将每个子任务路由给合适的专家代理。协调器随后汇总各专家的响应，以制定最终的全面答案。
对于更线性的工作流，**序列（Sequential）**模式更合适，它的运作方式类似于数字装配线，一个代理的输出直接成为下一个代理的输入。
其他关键模式专注于质量和安全。**迭代细化（Iterative Refinement）**模式创建了一个反馈闭环，使用一个“生成器”代理创建内容，并使用一个“批评者”代理根据
### 部署与服务
agent需要多种服务才能生效，包括会话历史和记忆持久性等。
构建者可以依赖专门构建的、针对代理的部署选项，例如支持运行时及其它一切功能的统一平台 Vertex AI Agent Engine。对于想要更直接控制其应用栈、或在现有 DevOps 基础设施中部署代理的软件开发者，任何代理和大多数代理服务都可以添加到 Docker 容器中，并部署到行业标准运行时（如 Cloud Run 或 GKE）上
