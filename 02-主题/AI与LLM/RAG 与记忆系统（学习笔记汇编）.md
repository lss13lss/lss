# RAG 与记忆系统（学习笔记汇编）

检索增强生成（RAG）与记忆（Memory）是「让模型用上外部知识」的两条主线：RAG 解决单次问答的知识来源，Memory 解决跨轮次、跨会话的信息保持。这份汇编把散落在四篇笔记里的内容整理成一条完整链路：为什么要 RAG → query 理解 → 索引构建 → 检索与重排 → 评估与优化；后半部分整理记忆系统与长上下文的研究路线。

> [!info] 来源边界
> 原始笔记记录于 2025-07 ~ 2026-01，包含阅读摘录、外部资料整理与个人项目记录（`notes/项目.md` 中的部分内容是与 AI 的问答记录，本文只保留其中的技术结论，去掉了对话过程）。原文完整保存在 `backups/obsidian-cleanup-20260921/整理前笔记与配置.zip`。

## 1. 为什么需要 RAG

大模型直接回答有三类硬伤：

1. **时效性**：语料不能及时更新。
2. **安全性**：部分数据是隐私的，不能拿去训练。
3. **精确性**：有时需要模型严格按照说明文档回答，避免幻觉。

RAG 的核心思想是外部构建知识库，为模型提供专业参考知识来辅助生成。

## 2. 整体流程

```text
query → （query 理解）→ 检索 → 召回文档片段 → 重排/过滤 → 拼接进 prompt → LLM 生成
                     ↑
        文档解析 → 内容理解 → 分块 → 向量化 → 索引
```

四段职责：

1. **query 理解**：需求识别、query 改写与补充、核心词提取、纠错。
2. **原始文档处理**：内容理解、文档解析、多模态内容理解、数据增强（生成摘要）。
3. **分块与索引**：常见向量索引、倒排索引、图数据库。
4. **召回**：向量检索、关键词检索、图谱检索、agent 流。

## 3. Query 理解

用户提问不一定适合直接检索，需要按业务需求分类（时效性分类、映射到意图列表等）。改写包括：多轮对话的省略补全、核心搜索词提取、同义词扩写与纠错。

| 模型 | 耗时要求 |
|---|---|
| 搜索时效性模型 | 约 100ms，对耗时要求高 |
| 多轮改写模型 | 约 500ms，需要较强的语义理解与推理 |

## 4. 内容理解与索引构建

1. **文档解析**：从原始文档提取重要信息、去除噪音；图片与表格需进一步理解，生成可用于检索的文本。
2. **信息增强**：针对文档片段生成可能的问题、摘要，构建图（提取实体与关系）。
3. **构建索引**：召回文本与检索文本**可以是两套**——倒排索引的检索文本通常较短，是多粒度切词的文本。
4. **文本切分**：基于规则（特定符号、递归切分）或基于模型（保证切分后的语义完整性与独立性）。

## 5. 分块与向量化

- **分块**：考虑块大小与 embedding 模型的处理能力，配合文本分割器与元数据。
- **向量化**：并非简单取最后一个 token 向量，而是通过嵌入模型 + 池化策略把一段文本压缩成固定长度的高维向量。
  - 取最后一个有效 token 的隐藏状态（它能捕捉之前的完整上下文）；
  - 或 CLS 池化（训练让开头插入的 [CLS] 标记承载整段摘要信息）。

## 6. 检索方法

### 6.1 倒排索引与 BM25

对文档内容切词生成倒排索引，检索时先分词 → BM25 打分 → 取 TopN 喂给 LLM。

BM25 基于查询词在文档中的出现频率与在整个语料中的出现频率计算相似度，是对 TF-IDF 的改进：词频非线性饱和（避免高频词过度影响）、文档长度归一化、IDF 优化（提升区分性强的词项权重）。

### 6.2 向量检索与索引结构

向量与文本都转成 float 数组，召回时计算向量相似度（常用 L2 距离/内积/余弦）。

| 索引 | 机制 | 特点 |
|---|---|---|
| Flat | 暴力计算查询向量与所有向量块的距离 | 全量召回，性能低 |
| IVF | K-means 把数据分成 C 个簇，先找最近若干聚类中心（粗粒度）再在倒排表内细粒度搜索 | 高召回、性能中等 |
| PQ | 把 D 维向量拆成 m 个子向量分别量化，用码字组合表示原向量 | 压缩存储 |
| HNSW | 多层小世界图，从顶层贪心向下层导航 | 高召回、性能高；半精度几乎不损失召回 |

### 6.3 混合检索

一路倒排（关键词）+ 一路向量（语义），按权重合并候选集，再做重排。

## 7. 召回与重排

召回模型只看一眼：query 与 doc 各自打成向量，点积完事，doc 侧信息被冻结在内存里，看不到 query 的上下文。重排阶段数据量已变少、计算量不再是瓶颈，可以把 query 和 doc 完整喂给 Transformer 做 cross attention——相当于开卷考试，能解决同义词、句法变换、实体对齐、长距离依赖等问题。

> 召回负责快刀斩乱麻，重排负责拿放大镜逐字逐句对答案。

主流重排模型基于 BERT 架构，百兆级别使用最多。

**二级检索的五种做法**

| 方案 | 做法 | 案例效果 |
|---|---|---|
| 混合检索 + 重排 | 一级多路召回（向量 + BM25），按权重合并保留 Top-N；二级用轻量重排模型筛 Top-K | 金融问答：FAISS + Elasticsearch BM25 一级，ColBERT 二级，召回率 +18% |
| 元数据过滤增强 | 分块时抽取时间/作者/类型等元数据；一级粗召，二级按解析出的元数据条件过滤 | 法律文书：Top-100 → 按「法院层级=最高法院」过滤，准确率 +25% |
| HyDE 假设文档 | LLM 按 query 生成假设答案，与原 query 一起编码加权后检索 | 需调低温度避免偏离原意图 |
| 分块重组与上下文填充 | 滑动窗口重叠分块（如 512 token、重叠 15%），对相邻分块合并重构上下文 | 注意合并后长度别超上下文窗口 |
| 知识图谱引导 | 从 query 提取实体链接到图谱，按关系扩展查询后重新检索 | 适合医疗、金融等专业术语扩展 |

**二级索引架构**（解耦检索与生成）：

- 一级索引（Key Index）：存储关键信息（摘要/实体/关键词）的向量化表示，用于快速相似度计算。
- 二级索引（Raw Text Index）：存储原始文本块，与一级索引双向映射。
- 流程：关键信息定义（轻量 LLM 生成摘要 + NER 抽实体 + TF-IDF/TextRank 提关键词）→ 关键信息融合成字符串 → Sentence-BERT 编码入库并记录映射 → 一级混合检索 → 二级元数据过滤与轻量重排 → 按 ID 映射回原始文本 → 上下文压缩与结构化 Prompt 生成。

**LangChain 落地要点**：`Document` 的 metadata 存关键信息、page_content 存原文；`EnsembleRetriever` 用 weights 调向量与关键词权重；重排可用内置 `CohereRerank` 或自建 ColBERT 服务；关键信息提取（spaCy/T5）需在 LangChain 外部做，通过预处理流水线注入；性能上可用 callbacks 记录耗时 + Celery 异步、cache 集成 Redis 缓存高频查询。

## 8. 高级检索策略

- **HyDE**：LLM 生成 k 个「假答案」，把假答案与原始 query 一起向量化并取平均，融合向量里既有问题信息也有「答案该长什么样」的模式信息，增强召回。
- **FLARE**：生成过程中多次召回——每生成固定 n 个 token、每生成一个完整句子、或把 query 分解为子问题后按需召回。
- **主动召回**：通过 prompt 与示例让模型在需要知识时按格式输出 `[Search("模型提出的问题")]`；召回后把答案放到 query 前、去掉标识继续生成；下次生成标识时把上一次召回内容从 prompt 移除（类似 toolformer 模式）。
- **Self-RAG**：引入 reflection tokens（Retrieve / Critique 两类），检查是否需要检索，以及输出的相关性、完整性、检索片段是否支持输出观点。经典 RAG 无差别合并召回上下文，召回内容可能与 query 无关或矛盾，窗口较小时尤其有害。
- **Graph RAG / KG 增强**：对 query 提实体、构造子图形成上下文；或走 NL2Cypher 做图查询，把子图转成文本片段增强上下文。
- **负难样本采样**：随机采负例质量不可控（过易导致过拟合、无法区分难负例）。Top-K 难负例（用稠密检索模型打分取 Top-K）保证难度但可能误伤真正例；困惑负样本（SimANS）认为「与正例语义相似度接近」的负例同时在梯度均值与方差上更优——与 query 无关的文档信息量不足应给低分，很可能相关的文档可能是假负例也应给低分，只有与正例接近的才应给高分。实现上以 `s(q,di)` 与 `s(q,d+)` 的差值为输入，配合单调递减函数（如 e^(−x)）作为采样分布。

## 9. RAG 的评估

**为什么要评**：RAG 依赖检索与生成两个模块协同，单独优化某一个模块可能无法提升整体性能。

**合成测试集**：① 选一个随机块作为根上下文；② 从向量库检索 K 个相似上下文；③ 把根上下文与相邻上下文拼接成更大的上下文；④ 用大上下文 + num_questions 生成问答对。然后在 RAG 上跑这些问题得到预测结果，同时记录支撑响应的上下文列表。

**评估分层**：检索模块评估、生成模块评估、端到端性能评估。

**关键指标**：答案准确性、答案相关性、上下文相关性。

**框架**：
- **RAGAS**：Faithfulness（把答案拆成多个陈述，检验每条与上下文一致性，按支持数/总数算分）、Answer Relevance（让 LLM 反向生成可能的问题，与原问题算相似度取平均）、Context Relevance（筛出与问题直接相关的句子，占上下文总句数比例）。
- **T-RAG**：检索性能、生成性能、端到端（回答准确性/相关性/完整性）+ 可视化工具。

**自动化指标**：BLEU（nltk）；ROUGE（基于 n-gram 重叠，偏召回，衡量覆盖了参考摘要多少内容）；METEOR（考虑同义词、词干、词序与语义相似性）；TER（改成参考翻译所需的最小编辑操作数）。

**用大模型当评估者**：
- 拆分评估维度：维度太多容易格式错误导致解析失败，可以每个维度调一次。
- 合并评估维度：维度太细模型理解不了，可以把逻辑性、通顺性、智能性合并。
- 提供详细评估规范 + 少量示例，否则模型很难给出理想结果。

**LLM 应用评估的一般思路**：针对 bad case 优化 → 构建验证集 → 建立自动评估方法 → 整体评估。多维评估维度参考：知识查找正确性（中间检索结果能否回答问题）、回答一致性（是否偏题）、回答幻觉比例、回答正确性（最核心）、逻辑性、通顺性、智能性。客观题可直接对比答案，也可用 BLEU 等算相似度。

## 10. 优化清单

**生成部分**：
1. 提升直观回答质量：构造 bad case、修改 prompt 要求回答具体、去掉多余部分；答案长则分段，有多点则分点标号。
2. 标明知识来源，提高可信度。
3. 构造思维链（如两步 CoT，第二步做反思）以消除幻觉。
4. 在检索 LLM 之前加一层指令解析 LLM，把格式要求与问题内容拆开——这就是 Agent 机制的雏形：用一个 LLM 理解指令、判断该调什么工具，再针对性调用。

**检索部分**：
1. **知识片段被割裂导致答案丢失** → 优化文本切割方式，针对性构建分割规则，或训练专用文本分割模型按语义主题切块。
2. **需要长上下文概括回答** → 优化知识库构建：对长文档先概括总结，或预设提问让 LLM 先回答，把可能的答案预填成独立 chunk。
3. **关键词误导**（次要关键词影响主要关键词匹配）→ 用 LLM 改写 query，去除次要关键词与错字漏字。
4. **匹配关系不合理**（召回强相关文本却不含答案）→ 根因是向量模型构建的是「配对」语义相似度而非「因果」语义相似度；例如「今天天气怎么样」会认为「我想知道今天天气」比「天气不错」更相关。
5. **embedding 表示 text chunk 偏差大** → 用更小的 chunk 配合更大的 top-k，smaller chunk 的 noise 更小、更大 topk 能组合更丰富的上下文。
6. **协调查询与文档的语义空间** → query 重写（用 LLM 生成指导性伪文档并与原查询结合，或多查询检索）、嵌入变换（在查询编码器后加适配器并微调）。
7. **长文档关键信息** → 分块索引法、文本摘要法、多级标题构建摘要法。

## 11. LangChain 实战要点

**六个组件**：模型（各模型接口与输出解析）、prompts（提示工程）、数据检索、记忆（短时/长时）、链（核心机制，封装功能组合）、代理（让模型自主调用内外部工具）。

**索引五步**：Loading（文档加载器）→ Splitting（文本分割器）→ Storage（把文档块以嵌入形式存入向量库）→ Retrieval（按余弦相似度检索相似嵌入片）→ Output（把问题与检索片段交给 LLM 生成答案）。

**切分器对比**：

| 切分器 | 特点 |
|---|---|
| CharacterTextSplitter | 直接指定字符长度，适合结构化文本（代码、日志）；可能在句子中间截断 |
| RecursiveCharacterTextSplitter | 按 `["\n\n","\n"," ",""]` 优先级递归分割，尽量保留段落结构，避免句子中间截断 |
| TokenTextSplitter | 按 token 计数切分 |
| SentenceSplitter | 保证每块是完整句子；对不规范标点敏感 |
| SpacyTextSplitter | 基于语言模型分割，支持实体识别等；需额外装 spaCy 模型 |
| LineSplitter | 按换行符分割，适合代码或逐行数据 |

常用参数：`chunk_size`、`chunk_overlap`、`length_function`、`separators`。

**输入输出**：提示模板（PromptTemplate / ChatPromptTemplate / FewShotPromptTemplate + 示例选择器如 SemanticSimilarityExampleSelector）、语言模型（LLM / Chat Model / Embedding Model）、输出解析（Pydantic JSON 解析器、OutputFixingParser、StructuredOutputParser + ResponseSchema）。

**链**：Sequential Chain（顺序链）、RouterChain（按标准动态选择下一个链，含 LLMRouterChain 与 MultiPromptChain；无法决定时走 default_chain）。

**记忆**：ConversationChain、ConversationBufferMemory、ConversationBufferWindowMemory、ConversationSummaryMemory。

**检索增强**：相似性搜索 `similarity_search(query, k=3)`；MMR `max_marginal_relevance_search(query, k=2, fetch_k=3)`（同时考虑与查询的相关度和文档之间的差异性）；元数据过滤 `filter={"source": "..."}`；自查询检索器 SelfQueryRetriever（用 LLM 从问题中解析搜索词与元数据过滤条件）；上下文压缩 ContextualCompressionRetriever + LLMChainExtractor（先向量检索拿候选，再用 LLM 按 query 压缩，只保留相关部分）。

**问答链模式**：`RetrievalQA.from_chain_type`，`chain_type` 可选 map_reduce（速度慢、结果偏差——分文档独立回答，信息跨文档时看不到全貌）、refine（把历史回复与新文档组合成一个 prompt 序列请求改进，类似 RNN 思路，能解决信息分散问题）、map_rerank（按问答质量调整文档顺序）。

**Agent 获取上下文的几种方式**：全量历史对话、滑动窗口取最近部分、抽取历史对话中的实体、用知识图谱获取实体及联系、阶段性总结摘要、基于向量检索对话信息。

**基于 LLM + 向量库的文档对话架构**：先检索、后推理，重心在检索（推荐系统），推理交给 LLM 整合。检索需满足三点：尽可能提高召回率、尽可能减少无关信息、速度快。做法是把文本组织成二级索引（[关键信息] ↔ [原始文本] 一一映射），只对关键信息做 embedding 参与相似度计算，召回后映射回原始文本交给 LLM。

**垂直领域落地注意**：对 embedding 模型与 LLM 分别做垂直领域数据微调；LangChain 内置分句效果不佳时改用更好的文档拆分（如达摩院语义识别模型）、改进填充方式（判断中心句上下文的句子是否与中心句相关）、或对每段分别总结后用总结内容匹配。

## 12. 记忆系统

### 12.1 记忆的分类

| 类型 | 实现 |
|---|---|
| 文本记忆 | 完整记忆、近期记忆、检索记忆、外部记忆 |
| 参数化记忆 | 微调、知识编辑 |

### 12.2 文本记忆的三段流程

**记忆构建**

- 切分方式的取舍：chunk 不适合多轮对话；round 无法获取上下文、语境丢失；session 冗余度过高。
- 处理：保存摘要、主题切分、提取原子事实（用户画像）。
- 索引：基础索引（k-v 相同）与信息增强索引（关键字、标签、摘要、属性信息挖掘）。

**记忆管理** → **记忆提取**（原笔记在此处留了待补标记）

相关系统：memGPT、MemO。

### 12.3 mem0 的双阶段流程

- **提取阶段**：同时接收三个来源的上下文——新一轮交互、动态滚动的摘要、最近 m 条信息；用 LLM 提炼候选记忆；后台模块异步刷新长期摘要，避免记忆管理阻塞核心推理。
- **更新阶段**：候选记忆与向量库 Top-k 已有记忆做相似度对比，再智能决策：**添加**（新记忆）、**更新**（迭代或合并）、**删除**（移除矛盾或过时记忆）、**无操作**。

### 12.4 长上下文与记忆的研究路线（Agent RL 方向）

**信用分配（Credit Assignment）**：长序列任务中传统群体 RL 难以对单步动作给出精准反馈。解法是层次化群体结构——轨迹级群体（整体回报评估宏观优势）+ 步骤级群体（用重复出现的「锚点状态」构建微观组，计算单步动作优势）+ 动态融合；多智能体场景用异构群体策略与分阶段采样（如 Round-robin）平衡组内同构与异构样本。ALFWorld 等任务中步骤级分组使训练效率提升 30%+、冗余动作减少 50%；HotpotQA 等多智能体任务准确率提升 15%，泛化性优于单智能体 PPO。

**长上下文记忆管理**：

- **MemAgent**：把长文本分块，用 RL 训练模型选择关键信息更新**固定大小**的记忆库，回答阶段只依赖最终记忆。思路是把记忆提取建模为 MDP：文本切成固定大小的 chunk，每次读一个 chunk 并选择重要信息更新记忆，最后据记忆生成答案；与传统 GRPO 不同点在于每次 conversation 的 context 不同，把整个 conversation 视为 MDP，用最后一个 conversation 产生的记忆得到 answer 与 reward，再用于优化前序所有 conversation（RL 的意义就是让前序 conversation 都能得到训练）。3.5M 字符长文本中关键信息保留率 78%，优于基线 10%。
- **MEM1**：端到端 RL 训练智能体把推理与记忆整合进统一的内部状态，每轮更新压缩共享状态并策略性丢弃无关信息，实现跨任意长序列的**常数级内存**。解决的三个痛点：全上下文拼接导致计算与内存随 N 无限增长（O(N²) 计算、O(N) 内存）、超出训练长度的对话变成分布外数据、冗余信息稀释注意力。复杂任务序列中峰值内存仅增长 3%，任务完成率提升 20%。

**多智能体协作**：MLPO 分层框架只训练一个 Leader 模型来协调多个固定参数的 Peers；配合回溯式监督微调（增强 Leader 纠错）与多智能体引导强化学习（用群体响应优化 Leader 决策）。MATH 任务准确率 76.2%（比单模型高 6%），动态响应选择优于多数投票，任务扩展效率提升 40%。

**开放问题**：锚点状态定义的泛化性、非线性协作场景的信用传播；开放式任务中的关键信息识别、记忆压缩与推理链保留的平衡；非串行任务的角色动态分配与多领导者协同。

## 13. 部署与运维要点

（整理自项目笔记中对部署环节的梳理）

- **部署流程六环节**：模型导出与压缩优化（转 ONNX/TensorRT/vLLM 权重格式；量化、蒸馏、LoRA merge）→ 推理框架选择（vLLM 支持连续批处理与高效 KV Cache；TensorRT-LLM 适合 GPU；DeepSpeed-Inference / FasterTransformer 优化显存与算力）→ 服务化封装（FastAPI/Flask/Triton/Ray Serve，REST 或 gRPC，需支持流式输出）→ Agent 集成（RAG + Memory + MCP）→ 监控与评估 → 迭代。
- **典型架构**：

```text
用户请求 → API 网关 → Agent 层
                      ├─ RAG → 向量数据库（Milvus/Qdrant/FAISS）
                      ├─ Memory → Redis/数据库
                      ├─ 业务接口（MCP 工具）
                      └─ LLM 服务 → GPU 集群上的自研模型
```

- **部署模式**：单机 GPU（小规模内测）、多机多卡分布式（张量并行 + 流水线并行）、云端推理服务（弹性扩展）。
- **实用优化**：批量推理提吞吐、KV Cache 复用避免长对话重复计算、流式传输（WebSocket/SSE）边生成边返回、异构计算（CPU 预处理 + LLM 只做核心生成）。
- **监控指标**：性能（QPS、延迟、显存占用）；质量（问题解决率、幻觉率、用户满意度）；日志追踪（Prompt、模型输出、RAG 召回情况）。可配 Prometheus + Grafana 可视化。

## 14. 数据隐私与安全

**数据采集阶段**：字段级掩码（如 `138XXXX1234`）+ 上下文感知脱敏；差分隐私，在预处理阶段注入高斯噪声（ε=0.5–2.0），确保单条记录移除不会显著影响输出。

**模型训练阶段**：联邦学习（Secure Aggregation）实现「数据不出域」的联合训练；同态加密（如 Microsoft SEAL）支持密文推理。

**推理与输出控制**：

- 输入侧：正则过滤恶意模式（SQL 注入、XSS 等，拦截率 >99.5%）；基于 BERT 的意图分类检测诱导性提问（误报率 <3%）；记录历史交互，对异常请求模式触发二次验证；动态请求脱敏与上下文泛化。
- 推理侧：同态加密推理、安全多方计算、模型分割（中间层参数加密传输，防逆向）；对抗样本检测（FGSM 过滤器阻断 90%+）、模型水印（频域水印用于溯源）。
- 输出侧：多级过滤（规则引擎基于敏感词库、多模态检测用 CLIP+ResNet50、高风险输出转人工审核队列）；生成结果标识（显式水印 + 元数据附加记录生成时间、模型版本、输入提示）。

**同义词近义词的技术支撑**：上下文敏感的动态词嵌入（同一词如「苹果」在「发布新手机」与「富含维生素」中向量偏向不同语义）、多义词建模（不同义项映射到不同子空间）、词向量相似度 + 知识图谱层次关系、多头注意力分别捕捉不同维度的语义关联。
