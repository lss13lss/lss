# 判断新技术的五层框架与 hype 机制

> [!abstract] 最重要的判断是"它该跟谁比"
> 判断一个新技术的五层：理解原理 → 适用边界 → 自己的评价维度 → 找真正的对标对象（最关键）→ 再决定投不投入。hype 的产生 = 聪明的碰瓷式对比 + 打开想象力的叙事 + 只做到前两层的技术博主传播 + 认真比较后说"不必追"的人被误伤淹没。

## 一、核心方法：判断新技术的五层

1. **理解**：这个技术是什么；
2. **边界**：适用和不适用的范围；
3. **评价标准**：自己在什么维度上衡量它好不好；
4. **对标对象（最重要）**：它到底应该跟什么技术比——"这个技术出现总是为了做一件事"；
5. **决策**：前四步做完，再决定值不值得关注和投入。

作者自陈战绩：MCP、RAG、LangChain、Fine-tune、"小龙虾"（OpenClaw）在刚出时即公开反对；Agent、Claude Code、Skill 在第一时间呼吁关注（2025 年 2 月 Anthropic 内部还没关注 Claude Code 时）。

## 二、用五层拆 Jev

- **它是什么**：给模型当前状态和几个选项，输出各选项概率。抽象本质是 if-else / case-when。替代手段很多：BERT、GPT + JSON Mode、本地小模型读 logits 后归一化，"Jev 只是这些手段的其中之一"。
- **碰瓷式对比**：Jev 的叙事是拿自己跟 Frontier 大语言模型比速度和成本——"就好像健身博主去跟马斯克比薄肌"，挑一个自己能赢的维度。它是 prefill 机制、没有 autoregressive，竞争对手根本不是 GPT。
- **评价维度（AI referee 类技术）**：判断质量（Precision/Recall）、延迟、一致性（同输入同输出、可复现）、可校准；成本单独看，因为成本一直在降。
- **真正的对标**：网上段子说 Python 自带的 random 就能干类似的事；Jev 在很多任务上没有吊打 random。本地小模型 + logits + 归一化在四个维度上都很好，还不用给自己的系统平添一个看不透、不可调的外部云服务。
- **结论（视频作者立场）**：Jev 泯然众人、没有新意，"不值得我们学习，不值得花这么多时间去关注"。

> 对照阅读：[[02-主题/AI与LLM/Jev 技术与应用调研（2026-09-22）|Jev 技术与应用调研]]——用户自己的调研结论是"把选路、材料筛选、达标判断变成小问题交给 Jev"有价值且已有公开实现。本视频持相反立场（Jev 是 hype）。两文观点冲突，均未等同用户立场。

## 三、hype 产生的三个成因

1. **聪明的比较对象 + 打开想象力的叙事**。比较维度选大家需要的（成本、速度），且告诉大家一个"新的不知道的东西"。叙事上自称"针对机器优化"（对照大模型针对人类做 RLHF），大家立刻脑补出"AI 对 AI 的新范式"。作者反驳：所谓 Machine Native 就是过去二三十年所有软件在做的事——程序本来就是给机器看的，agents 本来就在做机器与机器的结合，Jev 没有往前多走。
2. **叙事天然利于传播，被"懂技术"的博主强化**。多数技术博主能读论文、跑代码（第一、二层已属少数），但没有第三、四层能力（见得不够多，找不到 best alternative），于是顺着发布者的叙事框架往下推，还因"我看懂了别人没看"的虚妄成为义务传播者；这类内容又天然被平台流量放大。
3. **反对声音被误伤、被淹没**。做完三、四层得出的"不值得关注"，和完全不学习的人结论一样，于是被一二层的人当成"第零层的草包"攻击（作者剖析 MCP 的视频下就有人身攻击）。真正懂的人（视频中提到田渊栋）只说"没必要"，不愿花时间解释，于是长期只剩肯定声音，心智不坚的人无脑跟进——"这对企业的管理层尤其是致命的"。

## 四、第四层吃功力，以及怎么把判断力教出去

- 第四层"吃过见过才知道什么重要"：要知道真正的 alternative、最好还能亲手实现出来证明（鸭哥真做了 OpenCode 对比小龙虾）。这是基本功 + 大量实践，AI 也帮不全。
- 只教结论会让学员像"站在第零层"：身边人都在吹 Jev 时甩出"不值得关注"，别人不会看文章，只会觉得你不懂。
- 课程新做法：先教大家**做出一个更好的 Jev**（本地模型 + 归一化），顺着叙事说"大家说得对，但我这个更好用"来取得信任，再说"其实这事没那么重要，我们做更重要的事吧"——"坐在旁边批判大家的人，一般在公司里不太受喜欢"。
