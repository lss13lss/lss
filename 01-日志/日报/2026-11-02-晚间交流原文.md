## 01 MyContext 个人上下文完成后的主动智能场景

因为我们这个整个项目呃个人上下文这里边已经做完了，然后现在在做的是主动智能，这里有两个典型的场景，一个就是在进行这个日会或者周会之前呢这个 Agent 呢它可以主动的去把你上一次呃对应的这个日会或者周会里边提到一些会议原文和这个呃整个这个归纳加载进来，然后它同时可以去拿到你近期的一些文档然后你的呃可能是你这个 Agent 的沉淀出来的一些数据，还有一些群聊信息，然后来判断你当前对于这个会议里边的针对你的这个代办的处理进度，然后它会归纳总结呃，一个你在当前会议里边，就是你需要同步的信息，然后你可能需要做的信息，还有你需要关注信息，大概是这三项，这是第一个场景。那另外一个场景就是盯群，这个功能其实是呃比如说他通过你过往的一些对话里边，他察觉到你有一些需求之后它可以在呃你所见的这个这些群聊里边去主动的盯对应的消息，就可能说你有些需求吧，或者说你这个项目一些关注点，然后呃你并没有在群里看这个消息，但是 Agent 呢它可以替你去发现，然后把对应的这个信息收集起来。啊提醒你，大概是这两个主动智能场景，但是在我理解里边，这个更有点像 Personal Agent 它在实际工作里面的场景，呃我们做的可能更多的是这种 Coagent 就是偏向于协作的这个场景吧，我不太确定，会议的那个其实还好，但是这个钉群这一块，我个人理解它并不是那么适合去呃作为一个主推的场景放到我们这个产品里边。

## 02 数据源获取、合规限制与项目推进阻塞

另外就是通过在做这个事情的时候，我们发现当前的这些工作推动吧，其实比较重要的是这种数据源的获取，比如说我们这里边要对接一些云盘，对接一些 PG 存储，ES 存储，对象存储等等这些东西。那这里边，啊其实真正的拿到数据之后去做处理，可能就是一些算法的设计吧，拿哪些字段，然后设置什么样的值，怎么聚合这块，但是呃我们现在难点在怎么拿到这些数据，就是一些数据它可能有加密需求，然后有些合规需求，有些能拿到有些不能拿到等等这些东西。我感觉这些才是去阻塞整个这个项目快速推进的一些难点。
