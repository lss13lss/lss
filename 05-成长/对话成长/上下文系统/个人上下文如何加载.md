# 个人上下文如何加载

一篇笔记存进知识库，就可以在本机搜到。它在哪一次对话里发挥作用，取决于 Agent 有没有根据眼前的问题找到并读取相关段落。本文记录 2026-11-09 的配置，两个客户端都使用同一份 [[05-成长/对话成长/上下文系统/BOOTSTRAP|启动入口]]。

## 一次提问经过哪些步骤

```text
本轮问题
  → 新会话首次处理实质任务：读取 BOOTSTRAP 和已确认的沟通约定
  → 判断本轮对话里的信息是否足够
      足够 → 直接回答
      需要个人材料 → 定位相关笔记 → 读原段 → 核对来源与日期 → 回答
```

**固定读取。** Codex 和 OpenCode 的入口都要求先读 BOOTSTRAP，再运行只读脚本 `tools/read_context.py`。不带参数运行时，脚本取出 [[05-成长/对话成长/个人画像/COMMUNICATION#已确认|已确认的沟通约定]]，连同来源路径和行号返回。新会话由此知道该用中文、渐进说明，并在个人口述时留出表达空间。同一会话复用已读内容；换了话题再选材，上下文压缩后按需重读。

**选择材料。** 用户点名笔记或章节时优先读指定位置。涉及个人偏好时查 USER 或 COMMUNICATION 相应章节；涉及项目状态时查 CURRENT 的相关条目，再沿链接核对项目页。项目已明确时可直接读项目页。读书判断会同时查眼前的事实与相关概念；回顾想法变化则需要不同时点的记录。只有需要追溯原话且普通笔记不足时，才定位日志或原始会话。

**检索与回退。** Agent 按问题选择目录，用关键词搜标题和正文，沿链接读取命中段及必要上下文。只记得日期的口述尤其要搜正文。已知准确标题时，脚本可按“库内文件路径、章节标题”两个参数读取该节。未命中就改用概念名、日常说法或日期，必要时扩大范围。固定读取脚本不可用时，直接读沟通约定；入口或证据仍不可用时，说明缺失项，继续有依据的部分。

## 四个提问会读到什么

1. **“把我刚才那段口述缩短一点。”** 当前消息已提供原文，结合沟通约定就能处理。如果还要求按晚间记录归档，再读取对应的原文保存约定。
2. **“继续上次的网站入门稿。”** 同一会话先看已有讨论；新会话可从 [[05-成长/对话成长/上下文系统/CURRENT|CURRENT]] 定位到 [[03-项目/个人项目/个人网站稿件/04-什么是 Agent，它能做什么|入门稿]]。要续写就读最新稿件；若用户问是否上线，则另查发布记录。文稿修改和网页发布是两个状态。
3. **“首页改完，怎么知道有没有用？”** 先找网站改版的目标，再用“指标”“衡量”“验证”去查 [[04-读书/在读/《精益创业》读书笔记|《精益创业》读书笔记]]。该笔记注明是助手整理、待本人审阅的候选稿。若只能查到改版动作和书中概念，就据此提出验证方法；判断成效还需要改版后的行为数据。
4. **“我以前和现在对网站定位的看法有什么变化？”** [[03-项目/个人项目/个人网站-定位调整-2026-11-01|网站定位记录]]保留了 11 月 1 日的方案解释和 11 月 5 日本人明确确认的主线。回答时要分别说明两段记录是谁的表述；若要解释当时为什么这么想，再追溯相应日期的原话。

## 哪一步仍可能漏掉材料

目前由 Agent 选择是否检索、用什么词和打开哪段原文；读取脚本只负责取出默认章节或指定章节。语义向量、混合检索和重排尚未接入这条流程。因此，即使相关书摘就在库里，Agent 也可能因为没想到跨到读书目录，或搜索词与原文差别太大而漏掉它。文件里搜不到时，准确的表述是“本次未找到对应证据”。更换索引后的效果，要用同一批真实问题对照验证。
